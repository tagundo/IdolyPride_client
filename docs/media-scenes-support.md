# 감상 모드의 라이브·MV 선택 경로

이 모듈은 명시적으로 분리한 전체 해금 감상 프로필의 정책입니다. 일반 계정의 획득 조건을 평가하거나 진행도를 추가하지 않습니다. `prepare_media_scenes(master_dir)`는 실제 공개 마스터 행과 참조를 검증한 뒤 `PhotoSceneAccess`를 반환합니다. 프로필·DB·마스터 파일을 저장하거나 새 곡·스테이지·사진·보상을 만들지 않습니다. 일반 모드에는 자동 적용하지 않습니다.

원본 일본판 6.1.1에서 MV 감상은 별도 `MV` 서비스가 아니라 촬영의 라이브 선택 경로를 사용합니다. `PhotographyWindow.InitializeAsync`의 `0x59c9090`이 `Photo.ListShooting`을 요청하고, `LivePhotographyScreenPresenter`가 해당 곡 목록을 읽습니다. 응답의 `musics[].isUnlocked`는 `0x59b541c`~`0x59b5454`에서 선택 항목의 잠금 상태로 전달됩니다. `User.Get.musics`만 채우는 것으로 이 목록을 해금했다고 판정하지 않습니다.

현재 공개 마스터의 `PhotoActivity` 29개·`PhotoQuestMusic` 94개·`PhotoQuestStage` 17개·`PhotoExpression` 26개를 사용합니다. 94곡은 3D 라이브 68곡과 MV 26곡이며 모두 실제 `Music` 행을 참조합니다. `Music` 전체 129개 중 3D 이용 가능 77개를 무조건 이 촬영 목록에 추가하지 않습니다. 대응 곡·스테이지가 없거나 참조가 잘못된 데이터는 가상 항목으로 보완하지 않습니다. 자산 참조 검증은 해당 파일을 이미 보관했거나 CDN에서 내려받았다는 증거와 별개입니다.

`unlock_media_musics(snapshot, master_dir)`는 촬영 목록에 실제로 있고 3D 이용 가능·자산 ID가 있는 곡의 `UserMusic`만 누락분 추가하고 추가 개수를 반환합니다. 기존 유효 음악 행과 알 수 없는 protobuf 필드, 다른 보유 데이터는 유지합니다. 이 helper는 전달받은 protobuf만 변경하며, 호출자가 감상 프로필의 저장과 일반 프로필 분리를 담당합니다. Movie 행의 해금은 위 `PhotoSceneAccess`에서 제공하며, 이 helper가 영화 소유 행을 별도로 만들지는 않습니다.

MV 확인 요청도 `Photo.CheckShooting`입니다. 원본 `0x59b8660`~`0x59b902c`는 MV에서만 빈 스테이지를 보내고 일반 3D 라이브는 선택한 스테이지를 보냅니다. `Music.IsMvMusic` (`0x4e7af24`)는 `mvAssetId`가 비어 있지 않은지를 사용하며 곡 ID 접두사나 `is3dAvailable` 반전을 사용하지 않습니다. 실제 영상 자산 이름은 원본 `Music.GetMv`/`GetMv1080p`와 다운로드 경로가 결정합니다. 서버는 영상 파일명이나 URL을 새로 만들지 않습니다.

이에 따라 실제 `PhotoQuestMusic`에 연결된 MV만 빈 스테이지로 확인할 수 있습니다. 잠긴 곡·알 수 없는 곡, 일반 3D 곡의 빈 스테이지는 거절합니다. 캐릭터·의상·헤어 배열이 제공되면 기존 소유권·동일 길이·착용 호환성 검사를 그대로 적용합니다. MV의 세 배열이 모두 비어 있는 경우에는 영상을 위해 3D 배우를 만들어 넣지 않고 읽기 확인만 허용합니다. 원본은 MV 판정 전에 이 배열을 선택 목록에서 구성한다는 것까지 확인했으며, 선택 목록 자체가 비는 실제 UI 상태는 아직 검증하지 않았습니다.

확인 요청은 계정·재화·필름·사진·예약 ID를 변경하지 않습니다. `Photo.CreateShootings`와 이미지 업로드·사진 생성은 계속 별도 미지원 범위입니다. 이 문서는 원본 정적 계약과 소스 구현 범위이며, 실제 게임의 MV 재생·3D 라이브 감상 완료나 새 설치 파일 검증을 뜻하지 않습니다.
