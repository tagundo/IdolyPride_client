# 첫 일반 라이브 실험 기능

개발 중인 v0.3.0 소스의 기능이며 **기본값은 꺼짐**입니다. Android·macOS 서버 앱에서 서버를 중지한 뒤 **첫 메인 라이브 실험 기능 사용**을 선택하고 시작합니다. 선택은 다음 실행에도 유지됩니다. 현재 배포된 v0.2.16에는 이 기능이 없습니다.

`/api.Quest/Start`의 첫 메인 퀘스트 `qt-main-1-001-01`만 지원합니다. 현재 소유 카드 다섯 장, 저장된 편성, 학습한 스킬·외형과 고정된 6.1.1 마스터로 결과를 계산합니다. 계산은 출처를 보존한 Solis `live-v5`의 **로컬 규칙**이며, 공식 서버의 점수·확률과 같다는 검증은 없습니다.

## 지원 조건

저장된 양수 `deckNumber`, `playCount=1`을 사용하며 대여 슬롯·티켓·스킵·자동 모드·포토·액세서리는 지원하지 않습니다. 게임 클라이언트가 `buddyDeckName`으로 보내는 자기 덱 이름은 허용합니다. 확장된 카드 성장 형태, 지원하지 않는 스킬 해금 경계, 일치하지 않는 저장 능력치는 DB를 쓰기 전에 거부합니다. 앱에 C ABI 1 네이티브 라이브러리가 포함되어 있어야 하며, 누락·호환성 오류가 있으면 서버 시작을 중단합니다.

네이티브 결과의 타임라인·점수·성공 여부를 응답에 담고, 현재 로컬 사용자와 저장 덱 다섯 장 및 점수 합계가 일치하는지 검증합니다. 메인 라이브의 rank type은 `Unknown`, B/C/D 표시 기준은 3600/3000/0입니다. 순위표와 상세 분석 로그 재생은 제공하지 않습니다.

## 첫 성공 정산

처음 성공했을 때 첫 퀘스트 마스터에 있는 다음 보상을 지급합니다.

- 카드 강화 아이템 `item-card_enhance` 290개
- 골드 500
- 무료 스톤 50개
- 액세서리 `ac-1-visual-02` 1개
- 매니저 경험치 50, 선택한 카드마다 경험치 40: 지급 후 매니저 레벨과 카드 레어리티의 실제 상한 적용

카드의 남은 경험치를 유지하고, 기존 카드 파라미터 검증기로 능력치를 갱신합니다. 강화 아이템을 소모하거나 수동 강화 시각을 바꾸지 않습니다. 응답의 보상과 전후 잔액은 현재 로컬 계정 기준입니다. 재화 상한·오버플로·잘못된 성장 상태·미지원 해금 경계가 있으면 전체 트랜잭션을 취소합니다.

첫 성공은 로컬 `UserQuest.lastClearedTime`으로 구분합니다. 새로운 요청 ID로 다시 도전하면 현재 덱으로 계산하고 최고 점수·성공 시각·횟수를 갱신하지만 **보상과 경험치를 다시 지급하지 않습니다**. 실패한 결과는 보상을 주지 않고 snapshot 바이트를 유지합니다. 팬·음악 숙련도·미션·캠페인·그 밖의 보상은 변경하지 않으며 `rewardCards.funAmount`는 0입니다. 이는 이번 실험 기능의 제한이며 원래 일반 라이브의 반복 보상 체계를 구현한 것은 아닙니다.

## 재시도와 계정 보존

`x-app-request-id`는 양수 uint64의 정규 십진수 문자열이어야 합니다. 프로필·요청 ID·요청 본문 SHA-256·RPC 경로·스키마/마스터/규칙 버전·무작위 uint64 seed·로컬 시각·전체 응답을 `main_live_attempts`에 기록합니다. 기록과 snapshot은 하나의 SQLite `BEGIN IMMEDIATE` 트랜잭션으로 저장합니다. 동시에 들어오거나 재시작 뒤 도착한 동일 요청은 계산을 다시 하지 않고 **원래 응답을 그대로 반환**합니다. 같은 ID에 다른 본문을 보내거나 저장된 스키마·마스터·규칙이 맞지 않으면 거부합니다.

일반 상태 변경은 기존 요청 기록을 보존합니다. 명시적인 snapshot 가져오기는 해당 프로필의 요청 기록과 로컬 레슨 시계만 함께 초기화하여 교체한 계정에 예전 응답을 사용하지 않게 합니다. 라이브 정산은 다른 프로필·설정·세션·레슨 시계·변경하지 않은 컬렉션과 알 수 없는 protobuf 필드를 보존합니다.

## 근거와 확인 범위

스키마와 마스터 버전은 `live_input.py`에 고정되어 있습니다. 계산기의 소스·라이선스·빌드 근거는 [네이티브 엔진 안내](../native-live-engine/README.md)에 있습니다. 요청·응답 필드는 추출한 6.1.1 descriptor, 보상·경험치는 `Quest`, `Reward`, `CardLevel`, `ManagerLevel`, `CardRarity`, `Setting` 마스터에 근거합니다. 공개 응답 참고 자료는 [sumire-sr-data c40ea107](https://github.com/Project-Hoshimi/sumire-sr-data/tree/c40ea107b9cc8e53ae1705f82a5c39cc9fe3be02/captures/2026-09-13_a12)에 고정했습니다. 같은 스테이지의 공개 기록 00019/00033은 실패 후 첫 성공을 보여 주며 이미 성공한 퀘스트의 반복 보상 근거로 사용하지 않습니다. 다른 계정의 잔액이나 상태 변경을 가져오지 않습니다.

실제 Linux 라이브러리와 새 로컬 스타터로 seed 123456을 사용한 검사는 4,781점·성공과 차트 183개를 반환했습니다. 경험치 반영 뒤 같은 seed를 사용한 새 요청은 7,042점을 계산했고 추가 보상은 없었습니다. 실패 계산·동일 요청·동시 요청·재시작·검증 실패 시 롤백과 계정 보존도 검사합니다. 이는 엔진/API 검증이며 실제 게임의 일반 라이브 화면 재생을 확인했다는 뜻은 아닙니다. Android 라이브러리 로딩과 macOS 앱 검증은 해당 플랫폼의 별도 검사 대상입니다.

선택적인 실제 네이티브 정산 검사를 실행하려면 다음 변수를 지정합니다.

```sh
IDOLY_LIVE_LIBRARY=/path/to/libidoly_live.so \
IDOLY_LIVE_MASTER_DIR=/path/to/audited/master-json \
.venv/bin/python -m pytest -q tests/test_main_live_native.py
```
