# v0.3.28 — Android 로컬 리소스 연결 수정

Android v0.3.25 클라이언트 제작 경로는 게임 API만 로컬 서버로 바꾸고, 리소스 SDK의 목록 주소는 공식 서버 주소로 남겨 두었습니다. 서버에서 받은 전체 리소스와 한국어 대사 자료가 준비되어 있어도 게임이 이를 우회할 수 있었습니다. 실제 배포 QA의 메타데이터·Unity 설정 해시와 새 진단의 로컬 리소스 요청 0건을 대조해 확인했습니다.

새 Android 클라이언트는 기존에 검증한 세 변경을 필수로 적용합니다. 리소스 목록을 `http://127.0.0.1:8080/`에서 받고, Unity의 로컬 HTTP 전송을 허용하며, 변경된 메타데이터와 설정에 맞춰 Unity 추출 식별자를 갱신합니다. 최종 서명 APK의 실제 주소·설정·식별자와 전체 멤버 해시를 검사합니다. 기존 계정이나 SDK 캐시를 삭제하지 않습니다. Downloads/IdolyPride 아래의 서버 리소스 보관 위치도 유지합니다.

이 문제에는 **Android 클라이언트 업데이트가 필요합니다.** 서버만 업데이트해서는 설치된 클라이언트의 주소가 바뀌지 않습니다. 일본어·한국어·영어 UI별 APK 중 원하는 하나를 설치합니다. 대사 자료의 언어는 서버의 언어 설정을 따릅니다. 준비된 한국어 ADV 3,091개와 원문으로 남는 401개의 기존 번역 범위는 달라지지 않습니다.

서버는 감상용 프로필의 사진 업로드 예약 ID 누락도 보완합니다. 원본 촬영 화면이 생성 RPC를 보내기 전에 빈 배열을 참조하던 문제를 실제 프로필 시작 경로에서 재현했습니다. 예약은 사진 생성이나 필름 소비를 의미하지 않으며, Firebase 이미지 업로드와 최종 사진 생성은 여전히 별도 복구가 필요합니다.

촬영 조건 거절에는 알려진 마스터 ID와 제한된 이유만 진단에 남깁니다. 리소스 진단에는 목록의 요청·응답 버전을 추가하고, 서버 중지 뒤에도 마지막 다운로드 작업의 실제 상태를 보존합니다. 요청 본문·계정 ID·인증 정보는 기록하지 않습니다.

Mac IPA에는 이미 로컬 리소스 주소와 HTTP 설정이 적용되어 있어 같은 제작 오류가 확인되지 않았습니다. 스토리 로딩 화면의 `RadioButtonView.SetDisabled` 예외와 아직 재현되지 않은 포즈 조건 거절은 해결됐다고 주장하지 않습니다. 호스트 검사와 최종 파일 검증은 실제 휴대폰의 비행기 모드 플레이 검증과 구분합니다.
