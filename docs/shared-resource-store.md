# 통합 앱의 공용 리소스 저장소

서버가 받은 Octo 원본 파일 하나를 서버와 게임이 함께 사용하도록 연결한다. 게임 SDK의 파일 캐시 모드(`OctoFullCache=2`)를 사용하며, 원래 게임의 번들 복호화·압축 해제 처리와 미디어 로더를 유지한다.

## 파일 흐름

1. 게임의 `PreDownload` 요청에서 플랫폼·업로드 버전·세대·크기·MD5를 읽는다.
2. 앱 내부 작업 스레드가 서버의 매니페스트와 대조하고 기존 파일을 재사용하거나 다운로드한다.
3. 크기와 MD5를 검증한 읽기 전용 파일에 SDK가 요구하는 이름과 확장자의 심볼릭 링크를 만든다. 파일 본문은 복사하지 않는다.
4. 게임의 원래 `PreDownload`를 다시 실행한다. 준비된 파일은 캐시 적중으로 처리하고 원래 파일 로더에 경로를 전달한다.

네트워크 대기·전체 파일 해시·파일 게시 작업은 Unity 콜백 스레드에서 실행하지 않는다. 큐와 경로 인덱스는 상한을 두며, 지원하지 않는 입력이나 준비 실패는 원래 다운로드 경로로 돌아간다. 원래 경로로 처리된 파일은 공용 저장 성공으로 집계하지 않는다.

현재 프로토타입의 네이티브 인덱스는 앱 프로세스당 8,192개 경로까지 유지한다. 한도에 도달하면 기존 SDK 다운로드를 사용하므로, 모든 리소스에서 중복 저장이 항상 없어지는 것은 아니다. 준비한 경로는 비동기 로더가 사용할 수 있어 인덱스에서 임의로 제거하지 않는다.

## 적용 범위

| 대상 | 저장 방식 |
|---|---|
| 통합 APK | 같은 앱 UID의 내부 저장소를 사용한다. 별도 서버 앱의 Downloads 보관 폴더는 ZIP으로 가져올 수 있다. 현재 통합 APK 프로토타입은 Android 11 이상이다. |
| 통합 IPA | 같은 앱 컨테이너의 리소스 파일을 직접 읽는다. Mac에서도 같은 IPA를 사용한다. |
| 기존 별도 서버·클라이언트 APK | 기존 HTTP 전달 방식을 유지한다. 서로 다른 앱의 저장소를 직접 공유하지 않는다. |

이미 설치된 게임의 예전 캐시는 자동 삭제하지 않는다. 이번 연결은 공용 저장소를 사용하는 파일의 추가 복제를 줄인다. 기존 계정·진행 자료와 과거 캐시를 일괄 지우는 기능은 포함하지 않는다.

## 통합 APK 언어 데이터

한국어·일본어·영어를 한 APK에 포함한다. 게임 시작 전에 선택한 언어의 Unity Data ZIP 하나를 준비한다. 이 ZIP은 클라이언트에 내장된 UI·데이터용이며, 서버가 다운로드하는 Octo 리소스와는 별개다. 다른 언어로 바꾸려면 게임을 완전히 종료한 뒤 다시 실행한다.

압축 파일의 원래 바이트를 유지하며, 원래 게임 DEX와 SDK 구성 요소를 보존한다. 최근 앱 복원으로 준비 단계를 건너뛰면 Unity를 생성하기 전에 서버 메뉴로 돌려보낸다.

## 확인 방법과 한계

`tests/test_shared_resource_store.py`, `tests/test_shared_resource_views.py`, `tests/test_shared_resource_broker.py`는 실제 임시 파일·다운로드 대역·IPC를 사용해 같은 inode를 읽는지, 확장자가 유지되는지, 취소·재시작 때 기존 파일이 남는지 확인한다. 원본 SDK의 타입·필드·진입점은 `tools/audit_shared_resource_cache.py`와 두 플랫폼의 명령 재현 도구로 검사한다.

빌드·서명과 호스트 검사는 실제 Unity 화면 검증을 대신하지 않는다. Android 기기 및 iPhone·iPad·PlayCover에서 첫 다운로드, 재방문, MV·음성·영상, 언어 전환, 서버 재시작을 확인한 뒤 정식 배포 여부를 판단한다.
