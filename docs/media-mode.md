# 감상용 전체 해금

[v0.3.24 홈 캐시 수정](home-media-cache-v0.3.24.md)은 포즈 탭이 전원 `撮影NG`로 표시되거나 이벤트 메뉴가 닫혀 있던 초기 응답을 보완한다. 서버 앱을 업데이트하고 게임을 완전히 종료했다가 다시 로그인한다.

최신 [v0.3.23 복원 안내](restoration-v0.3.23.md)는 촬영 포즈 146개, 교류 외출 4곳, 이벤트 스토리 59개·291편과 서버의 선택식 병렬 다운로드를 추가한다. 서버 앱을 업데이트하며 기존 게임 클라이언트를 그대로 사용한다. 이 버전은 공개 JSON 54개와 감상 마스터 7개를 포함한다. 아래의 이전 버전별 테이블 수와 다운로드 링크는 해당 버전의 기록이다.

Android v0.3.9 후보는 [APK 직접 다운로드](https://github.com/tagundo/IdolyPride_client/raw/refs/heads/downloads/local-server-v0.3.9/IdolyPride-Local-Server-Android.apk) 또는 [GitHub 파일 페이지](https://github.com/tagundo/IdolyPride_client/blob/downloads/local-server-v0.3.9/IdolyPride-Local-Server-Android.apk)에서 받습니다. 저장소 접근 권한이 있는 계정으로 GitHub에 로그인해야 합니다. 새 Mac 바이너리는 포함하지 않습니다.

서버 앱의 **감상용 전체 해금**을 선택하고 서버를 시작합니다. 모드를 바꾸려면 서버를 중지한 뒤 선택을 바꾸고, 게임은 타이틀로 돌아가 다시 로그인합니다. Android와 Mac의 기본값은 꺼짐이며 선택을 저장합니다.

감상 모드는 별도의 `media-state.db`와 감상 계정을 사용합니다. 기본 `state.db`의 계정·진행·선택·잔액을 바꾸지 않습니다. 감상 계정의 의상 선택과 스토리 읽음 기록은 다음 실행에도 유지합니다. CLI에서도 `serve --media-mode --master-dir ... --master-tag .../original-master/master-tag.json --asset-root .../original-master/assets --asset-base-url http://127.0.0.1:8080`으로 선택할 수 있으며 지정한 DB 이름 앞에 `media-`를 붙여 분리합니다. v0.3.8 감상 모드는 이 경로의 `media-master-tag.json`과 감상 마스터 여섯 개를 함께 준비해야 합니다.

현재 6.1.1 마스터에서 캐릭터 28명·의상 921개·헤어 1,113개·카드 503개를 준비합니다. NPC와 3D 자산이 없는 SD 전용 의상, 착용 가능한 의상이 없는 헤어는 생성하지 않습니다. 카드 성장은 초기 상태이며 재화나 개별 라이브 결과·보상을 추가하지 않습니다. 감상 진입을 위한 튜토리얼은 이 계정에서만 실제 마스터의 마지막 체크포인트로 준비합니다.

v0.3.9는 관객 후보 값이 0인 캐릭터만 보완해 라이브 촬영·360 LIVE에 관객을 준비합니다. 실제 팬 수와 기존 양수 후보 값은 유지합니다. 360 목록의 해금 조건 설명 참조 오류도 수정하며, 별도 [그래픽·촬영 화면 설정](presentation-settings.md)을 추가했습니다.

v0.3.8 감상 모드에서는 카페·라디오 등 촬영 업무와 장면 촬영의 의상 종류 제한도 해제합니다. 온천·암반욕 수영복 21개를 추가해 의상 921개·헤어 1,113개를 제공하며, 일반 라이브 촬영·360 LIVE에서도 선택할 수 있도록 클라이언트용 마스터를 함께 바꿉니다. 원본의 의상 분류와 헤어 호환성은 유지합니다. 자세한 범위는 [촬영 의상 안내](media-outfits.md)를 따릅니다.

v0.3.6에서는 촬영·360 LIVE 메뉴 조건을 위해 감상 계정의 두 번째 메인 지역 집계만 준비합니다. `UserArea.clearQuestCount`를 해당 지역의 실제 퀘스트 수인 3까지 올리며, 개별 퀘스트 기록·점수·날짜·보상·기본 계정은 변경하지 않습니다. 이로 인해 감상 홈의 현재 지역은 세 번째 지역이 될 수 있으며, 지원하지 않는 지역의 방치 레슨을 호출하지 않고 보상이 누적되지 않는 홈 상태를 제공합니다. 일반 계정의 진행과 레슨은 유지합니다. 원본 `ConditionExtensions.IsSatisfied(ConditionClearArea)`의 집계 비교와 두 메뉴의 잠금 경로를 확인했습니다.

같은 버전은 초기 희귀도 5인 카드의 기본 표시를 원본 규칙의 2로 준비합니다. v0.3.5 감상 계정에서 존재하지 않는 표시 1을 사용하던 404개 카드도 시작 시 필요한 표시 필드만 보완합니다. 기존 성장·유효한 표시 선택·의상·읽음 기록은 보존하며, 이 수정은 `Master.Card.GetDisplayData`의 일치 항목 없음 예외를 대상으로 합니다. 의상룸 복귀 프리징과의 직접적인 인과는 실제 재현으로 추가 확인해야 합니다.

스토리 3,277개를 미독 상태로 열고 기존 읽음 기록은 보존합니다. 메인·카드·캐릭터 스토리와 이벤트·특별 스토리의 조회·읽기·스킵을 지원하며 감상 모드에서는 스톤 보상을 주지 않습니다. v0.3.7은 [교류 메뉴·교류 스토리 읽기](company-support.md)도 지원합니다. 기념일의 별도 읽기 RPC는 아직 지원 범위 밖입니다. 자세한 범위는 [스토리 안내](story-read-support.md)를 따릅니다.

라이브 촬영 목록은 실제 3D 68곡과 MV 26곡을 사용합니다. v0.3.8은 별도 커버 버전 4곡을 포함해 이 목록과 촬영 스테이지 17개의 원본 표시·해금 조건을 해제합니다. 지역 조건이 원본에서 기간 없음(-1)으로 계산돼 재생 직전 기간 외로 판정되는 경로도 함께 처리합니다. 목록 전체 대조와 추가 누락의 범위는 [곡 목록 안내](media-music-catalog.md)를 따릅니다. MV의 빈 스테이지 요청도 원본 규칙으로 확인합니다. 재생 파일은 기존 게임 SDK 다운로드 경로를 사용하며 자산이 이미 다운로드됐다는 뜻은 아닙니다. 사진 업로드·새 포토 생성은 별도 미지원 기능입니다. [MV 경로](media-scenes-support.md)에 원본 호출과 제한을 정리했습니다.

촬영 옆의 **360 LIVE**는 별도 `PhotoPanorama` 경로입니다. v0.3.8은 원본 마스터로 검증한 MELODIES를 추가해 15곡의 목록과 3~6명 편성 확인을 제공합니다. 영상 MV와 지원 목록을 섞지 않으며, 구체적인 범위와 출처는 [360 LIVE 안내](panorama-support.md)에 정리했습니다.

v0.3.7 앱 데이터 번들에는 기존 45개 테이블 외에 교류용 JSON 4개가 추가돼 총 49개가 필요합니다. 빌더는 보존한 원본 팩에서 생성합니다. 기존 기본 계정 모드는 이전 데이터 번들로도 유지되지만 감상 모드는 필요한 표가 없으면 시작을 거절합니다.

실제 마스터를 사용한 별도 임시 계정에서 전체 개수·MV 준비 확인·의상 저장·스토리 읽기·반복 실행·기본 계정 파일 보존을 검사했습니다. Android v0.3.5 후보의 업데이트 설치 후 실제 체크박스 선택과 서버 시작, 별도 감상 DB 생성, 기존 계정 DB·설정 보존도 확인했습니다. 이 검사는 실제 게임의 MV·스토리 재생 완료와 구분합니다. Mac UI와 실행 엔진은 소스를 변경하고 관련 호스트 검사를 수행했으며 새 Mac 앱 실행 검증은 아직 없습니다.
