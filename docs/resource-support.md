# 게임 리소스 제공 범위

현재 v0.3.4 후보 소스는 **일본 Android 6.1.1**의 리소스 목록과 파일 요청을 로컬 서버로 연결합니다. GitHub에 배포된 서버 앱은 [Android·Mac v0.3.2](https://github.com/tagundo/IdolyPride_client/releases/tag/local-server-v0.3.2)이며, 새 후보는 아직 게시하지 않았습니다. iOS·한국판의 별도 리소스 목록과 Mac v0.3.2 앱은 이번 변경에 포함되지 않습니다.

기존 경로로 실제 게임을 실행했을 때 `Auth.Login → Master.Get → User.Get` 성공 뒤 `E209`를 관측했습니다. 원본에서 이 코드는 Octo 네트워크 시간 초과에 대응합니다. 새 서버 v0.3.4의 실제 Android 실행에서도 세 RPC는 성공했지만 원본 `E203` 통신 오류와 함께 SDK의 로컬 목록 요청 전에 멈췄습니다. Unity의 HTTP 설정 수정 뒤에도 오류가 남아 실제 메모리 매핑을 조사했고, 게임이 이전에 추출한 메타데이터를 계속 읽는 것을 확인했습니다. [연결판의 Unity 캐시 버전](resource-client.md) 갱신과 재실행을 검사 중이며, 다운로드 UI·홈·일반 라이브가 복구됐다는 검증 결과는 아직 없습니다.

## 후보 앱 사용 방식

후보를 받아 검사하는 경우 **서버 앱은 업데이트 설치**하고, **새 리소스 연결판은 추가 설치**합니다. 기존 공식 게임과 로컬 게임 앱은 유지합니다.

| 앱 | 식별자와 저장 방식 |
| --- | --- |
| 서버 | `game.qualiarts.idolypride.localserver`; 기존 서버 개발 서명과 DB 업데이트 경로 유지 |
| 새 리소스 연결판 | `game.qualiarts.idolypride.local.resources`; 기존 연결판과 다른 패키지·서명으로 나란히 설치, 앱 전용 캐시도 별도 |
| 기존 로컬 연결판 | `game.qualiarts.idolypride.local`; 기존 설치와 자료 유지 |

서버의 **아이프라 로컬 실행**은 새 연결판을 우선 열고, 설치돼 있지 않으면 기존 연결판을 엽니다. 새 리소스 경로를 검사할 때는 새 연결판을 사용합니다. 서버 앱과 게임은 같은 Android 기기에서 실행합니다.

1. 서버를 중지한 상태에서 **없는 게임 리소스 내려받기**를 선택합니다. 기본값은 켜짐이며, 끄면 이미 보관한 파일만 제공합니다.
2. **서버 시작**을 누르고 실행 중 상태를 확인합니다.
3. **아이프라 로컬 실행**으로 새 연결판을 엽니다.

다운로드 확인·파일 검사·완료 판정은 원본 게임 SDK가 담당합니다. 게임의 확인창과 진행 UI는 SDK가 필요한 파일을 판정한 결과에 따라 표시됩니다. 서버 앱의 전송 표시는 이 게임 UI와 별도의 기록입니다.

## 포함된 목록과 저장되는 파일

후보 데이터 묶음에는 기존 원본 마스터 202개·서버용 JSON 40개와 공개 Octo 파일 두 개를 넣습니다. 새 데이터 ZIP은 **84,041,457바이트**이며 SHA-256은 `ed68e0d09ad82b39de5f857b633ec6304ab7eea75e4fefe16f3a7c454c1c9f89`입니다.

Octo 목록의 **54,442개 참조는 메타데이터**입니다. 약 39.3GB의 전체 게임 리소스 파일이 APK에 들어 있는 것은 아닙니다. 게임이 실제 요청한 파일만 목록에 기록된 공식 CDN 주소에서 내려받습니다. 예상 크기와 MD5가 모두 맞은 원본 바이트를 임시 파일에서 검증된 캐시로 교체한 뒤 게임에 제공합니다. 일부 수신·시간 초과·길이 불일치·MD5 불일치는 완성 파일로 보관하지 않습니다.

공식 CDN에 파일이 남아 있는 동안 필요한 자료를 받아 보관할 수 있습니다. 이후에는 서버 캐시에 있는 파일을 사용할 수 있으며, CDN에서 사라진 미보관 파일은 새로 받을 수 없습니다. 전체 목록을 한꺼번에 내려받는 기능은 포함하지 않습니다.

서버 캐시는 Android 서버 앱의 전용 `files/data/octo-cache`에 보관합니다. 소스 실행에서는 지정한 데이터 디렉터리의 `octo-cache`입니다. 서버 재시작과 같은 서명의 앱 업데이트 후에도 유지되며, 서버 앱 삭제·데이터 지우기는 프로필과 이 캐시를 제거합니다. 게임 앱 자체의 다운로드 캐시는 각 게임 패키지의 저장 공간에 별도로 남습니다. 계정의 보유 포토·훈련 지역·VENUS 자료는 [개인 데이터 보존](event-preservation.md)의 별도 대상입니다.

## 서버 표시의 의미

**게임 리소스** 영역은 이번 서버 실행에서 관측한 두 전송 구간을 구분합니다.

| 표시 | 측정하는 내용 |
| --- | --- |
| 내려받은 양 | 공식 CDN에서 서버로 실제 수신한 리소스 바이트. 실패·재시도에서 받은 양도 포함할 수 있음 |
| 새로 보관한 파일 | 이번 실행에서 전체 크기·MD5를 확인하고 새로 보관한 파일 수 |
| 게임으로 보낸 양 | 서버가 게임 요청에 응답해 보낸 리소스 본문 바이트. 재요청과 Range 전송도 포함 |

이미 보관한 파일을 제공하면 새 수신 없이 게임으로 보낸 양만 늘 수 있습니다. **최근 요청한 게임 리소스 준비됨**은 최근 파일 요청의 준비 결과이며 게임 전체 자료의 준비 완료를 뜻하지 않습니다. 목록 응답, 기존 마스터 파일 전송, 전체 게임 앱 통신량도 서로 다른 측정값입니다. 이 값들을 합쳐 전체 다운로드 완료율을 만들지 않습니다.

## 개발용 형식과 경계

지원 목록은 애플리케이션 `212`, 버전 `205051`, 리비전 `1087`입니다. `OctoManifest`는 원본 protobuf 필드와 알려지지 않은 필드를 보존하며 로컬 연결용 `urlFormat`만 변경합니다. 초기 전체 목록의 protobuf 바이트도 해당 필드 외에는 그대로 유지합니다.

| 요청 | 처리 |
| --- | --- |
| `GET`·`HEAD /v2/pub/a/212/v/205051/list/0` | 원본 형식의 전체 목록 |
| `GET`·`HEAD /v2/pub/a/212/v/205051/list/1087` | 같은 리비전과 로컬 URL 형식, 변경 파일 목록은 비어 있는 응답 |
| `/octo/{v}/{type}/{o}/{g}`의 `GET`·`HEAD`·단일 `Range` | 목록에서 확인한 버전·종류·오브젝트·세대와 일치하는 원본 파일 |

목록의 HTTP 헤더는 원본 `Accept` 형식과 내장 SDK 애플리케이션 키를 확인합니다. 응답은 원본의 **16바이트 IV + AES-256-CBC/PKCS#7 protobuf** 형식을 사용합니다. `{type}`은 `assetbundle` 또는 `resources`입니다. 다른 목록 리비전의 변경 이력은 보관하지 않아 `409`로 거절하며, 알 수 없는 경로·파일은 제공하지 않습니다.

파일의 업스트림 주소는 목록의 식별자로 만든 고정 공식 CDN HTTPS 주소만 허용합니다. TLS 검증을 유지하며, 요청 URL에서 임의의 원격 주소나 로컬 파일 경로를 받아 사용하지 않습니다. 캐시 누락 시 동시 요청은 같은 다운로드를 공유합니다. `HEAD`도 실제 검증 파일이 준비된 뒤 응답하고, 불가능한 Range는 다운로드 전에 거절합니다. 캐시 전용 모드의 누락은 `503`, 취득·검증 실패는 `502`로 응답합니다.

서버 중지는 새 요청을 막고 진행 중인 업스트림 취득을 취소합니다. 이미 열린 검증 파일의 응답은 마무리될 수 있습니다. 전송 알림은 관측용이며 파일 검증·제공·게임의 완료 판정과 분리합니다.

### 데이터 묶음 만들기

`public-octo` 디렉터리는 `manifest.pb`와 `settings.json` 두 파일만 준비합니다. 설정에는 해당 원본 클라이언트의 공개 SDK 정보와 목록 해시를 넣습니다. 계정·Firebase 인증 자료와 보존한 개인 응답을 이 디렉터리에 넣지 않습니다. 설정 값이나 키를 문서·로그에 출력하지 않습니다.

스키마와 기존 마스터를 준비한 저장소 루트에서 실행합니다.

```sh
uv run python tools/build_server_payload.py \
  --data-dir data \
  --output /tmp/IdolyPride-ServerData-v0.3.4.zip \
  --octo-data /path/to/public-octo
```

앱 빌드는 [Android 서버 안내](../android-server/README.md)를 따릅니다. 공개 Octo 두 파일을 넣지 않은 기존 데이터 묶음도 기존 서버 경로로 사용할 수 있지만, 새 리소스 경로는 활성화되지 않습니다.

## 검증과 남은 범위

프로토콜 단위 검사에서는 초기·동일 리비전 응답, 헤더·경로 검증과 알 수 없는 필드 보존을 검사했습니다. 보존한 원본 목록의 재암호화·독립 디코딩 및 실제 목록을 제공하는 로컬 HTTP 검사도 통과했습니다. 캐시·HTTP 합성 검사는 잘못된 크기·MD5·경로, 동시 요청, `HEAD`·`Range`, 실패 후 정리, 종료 중 취득 취소와 전송량 분리를 다룹니다.

이 검사는 새 연결판에서 원본 다운로드 UI가 표시됐거나 홈·라이브가 완료됐다는 결과가 아닙니다. 원본 SDK를 통한 실제 취득과 화면 진행은 계속 검증하고 있습니다. 이번 리소스 경로는 포토 촬영·이미지 트레이닝 생성·이벤트 라이브·VENUS 대전·보상 정산을 추가하지 않습니다.
