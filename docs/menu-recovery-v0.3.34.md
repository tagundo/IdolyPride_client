# v0.3.34 메뉴 읽기 복구 범위

[v0.3.34 배포·검증 기록](releases/recovery-v0.3.34.md). 소스 `4bf0325d90ac36c9f3a5a9f10c55ef7d0e456118`, [Actions 43722420006](https://github.com/tagundo/IdolyPride_client/actions/runs/43722420006)에서 전체 검사와 다섯 필수 검증 단계를 통과하고 세 파일을 게시했습니다. 아래 읽기 범위를 실제 전투 복구와 구분합니다.

이번 묶음은 일반 미션의 세 탭과 일일·콘테스트·타워의 목록을 함께 다룹니다. 저장된 목록과 기록을 읽는 경로의 복구이며 해당 모드의 전투·보상·전체 진행 복구를 뜻하지 않습니다. 아래 표의 호출 수를 서로 독립된 완성 기능 수로 세지 않습니다.

## 일반 미션

기존에는 Mission.List가 저장된 카드 레벨 도달 미션 한 행만 반환했습니다. 이제 현재 계정에 실제로 저장된 Daily·Weekly·Normal 미션 중 원본 마스터와 현재 임계값·보상 표시 참조를 확인할 수 있는 행을 반환합니다. 이미 저장된 조건부 일반 미션도 유지하며 진행도·수령 상태를 보고 새 자격을 계산하지 않습니다.

Photo·이벤트·교류 전용 미션은 일반 탭에 섞지 않습니다. 이 행과 현재 마스터에서 찾을 수 없는 과거 행은 User.Get 원본에 그대로 남습니다. 실제로 저장된 일반 미션이 없는 경우에는 원본 클라이언트가 처리하는 빈 목록을 반환합니다. 모든 저장행의 ID가 현재 마스터에 없는 상태나 알려진 행의 잘못된 임계값·표시 보상은 명시적으로 거절합니다.

이 조회는 미션을 새로 만들거나 일일·주간 기간을 초기화하지 않습니다. Mission.Receive, 다음 임계값으로의 수령 처리와 보상은 이 묶음에 포함하지 않습니다. 기존에 구현된 카드 강화 시 카드 레벨 도달 미션을 갱신하는 범위는 유지합니다.

## 일일·콘테스트·타워 목록

| 화면과 호출 | 제공하는 자료 |
| --- | --- |
| 라이브 메뉴의 Quest.Top | 기존 메인 목록과 함께 일일·콘테스트·메인 타워의 실제 마스터 목록 및 저장된 결과 |
| 일일 Quest.ListDaily | 표시 가능한 일일 영역의 마스터 순서·퀘스트 목록·기존 클리어와 점수 |
| 콘테스트 Quest.ListContest | 실제 콘테스트 영역과 퀘스트의 기존 결과 |

| 타워 상위 화면 Quest.TowerTop | 메인·표시 가능한 서브타워 목록과 실제 진행이 있는 경우의 조회용 현재 위치 |

영역·퀘스트의 소속과 저장된 참조를 검증하고, 모드별 기록을 분리해 메인 진행 판정에 다른 모드의 결과를 섞지 않습니다. 클리어 시각·최고 점수·점수 등급·기존 순위·일일 클리어 수를 보존합니다. 타워의 조회용 현재 위치도 저장된 클리어 기록으로 계산하며 새 진행을 저장하지 않습니다.

조건이 있는 일일·서브타워 영역은 해당 계정의 실제 클리어·점수 등 결과가 있을 때 과거 자료로 표시합니다. 빈 진행 행 하나만으로 노출하지 않으며 현재 이벤트 일정이나 개최 상태로 취급하지 않습니다. 조건이 없는 목록도 전투 입장 권한을 새로 부여하지 않습니다.

새 일일·콘테스트·타워 응답의 영역 해금과 플레이 가능 값은 비활성 상태입니다. 도전 횟수·벌크 편성·무료/유료 입장권·캠페인 보상·전투 정산을 만들지 않습니다. 기존 메인 퀘스트의 지원 범위와 진입 상태는 유지합니다.

## 기존 계정과 교류 메뉴

일반 계정에서 명시적으로 가져온 응답 fixture는 기존 우선순위를 유지합니다. 로컬 목록 조회는 snapshot·계정 식별자·설정·유효 세션·다른 계정의 자료를 변경하지 않습니다. 명시적인 snapshot 가져오기는 기존 계약대로 이전 세션을 무효화하므로 이후 다시 로그인해야 합니다.

일반 모드 Company.Top·Company.EnjoyCharacterTop은 이번에 무조건 개방하지 않습니다. 포인트 0이나 레벨 1이라는 값만으로 첫 보상을 이미 받았는지, 어떤 단계의 보상 수령 이력이 있는지 판단할 수 없습니다. 월별 급여 역시 실제 정산·수령 근거가 필요합니다. 이 값을 추측해 일반 계정의 보상 버튼이나 수령 상태를 만들면 기존 계정과 어긋날 수 있습니다. 별도 감상 계정의 기존 교류 읽기 범위와 명시적 fixture는 유지합니다.
