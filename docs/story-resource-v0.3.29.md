# v0.3.29 — 스토리 파일 주소와 Android 로딩 화면 복구

v0.3.28의 21번 진단은 인터넷 연결 상태에서 수집됐습니다. 원본 리소스 54,442개의 검증은 완료됐고 캐시 전송 10건이 성공했지만, 스토리 파일 두 주소가 목록 확인 단계에서 404로 거절됐습니다. 이 기록은 오프라인 플레이 성공을 증명하지 않습니다.

실패한 주소의 SHA-256 앞 16자리를 원본 목록과 고정된 한국어 자료로 대조했습니다. `25d1a14e7fffa4db`는 `adv_event_2510_01_01.txt`, `6c10406869023b10`은 `adv_main_01_01_02.txt`입니다. 두 요청 모두 원본 objectName과 번역본 generation이 결합돼 있었습니다. SDK 내부 UPDATE 구현까지 확인한 상태는 아닙니다.

서버는 검증된 번역 목록의 원본·번역 행에서만 이 주소 조합을 별칭으로 만듭니다. 별칭은 기존 번역 레코드로 연결되므로 파일 크기·MD5·캐시 키와 준비된 번역 파일의 검증을 유지합니다. 다운로드 목록이나 파일 수를 늘리지 않으며, 알 수 없는 이름·버전·generation을 추측해서 연결하지 않습니다. 기존 번역 패키지와 Downloads 리소스를 다시 받을 필요는 없습니다. 실제 고정 한국어 자료 두 개로 GET·HEAD·Range 응답과 전체 해시를 검사했습니다. 이 서버 변경은 Android와 Mac에 공통 적용됩니다.

Android의 `RadioButtonView.SetDisabled` 예외는 스토리 회전 안내 화면에서 발생했습니다. 원본 UI 파일의 가로·세로 버튼에는 `_fade` 참조 두 개가 비어 있었고, 각 버튼에는 대상 CanvasGroup이 이미 존재했습니다. 로딩 화면도 같은 두 CanvasGroup을 참조하고 있었습니다. 빌드 시 정확히 두 참조를 연결합니다. 49,540바이트 파일 중 2바이트만 달라지며, 나머지 객체·텍스트·직렬화 구조는 그대로입니다. 실행 중 예외 처리나 프레임별 작업을 추가하지 않습니다.

새 Android 클라이언트의 Unity 추출 식별자는 수정된 UI 파일의 해시도 포함합니다. 기존 계정·설정·SDK 다운로드 자료를 삭제하지 않습니다. 이 UI 수정은 Android에만 적용하며, Mac용 IPA는 이번 변경 대상이 아닙니다.

서버 수정에는 서버 앱 업데이트가, Android UI 수정에는 클라이언트 APK 업데이트도 필요합니다. 원본 코드·파일·호스트 HTTP 검사와 실제 기기의 플레이 검증은 구분합니다. 실제 Android 비행기 모드 플레이, 해당 UI 예외의 기기상 해소, Mac 오프라인 플레이는 아직 검증하지 않았습니다. 사진 생성·업로드와 현재 포즈 촬영 조건 오류도 이번 변경으로 해결됐다고 주장하지 않습니다.
