# 서버 설정·유저 관리 구현 범위

2026-11-16 개발 소스 기준입니다. **공개 릴리즈 기록이 아닙니다.**
현재 공개 다운로드는 v0.3.35를 유지하며, 아래 기능은 원격 통합 검사와 실제 플랫폼 검증을 진행합니다.

## 서버 설정

시작 검사는 실제 descriptor의 게임 메서드, 원본 마스터 목록·파일 크기, 저장 위치의 쓰기/읽기·여유 공간, HTTP JSON 응답과 소유한 gRPC 리스너를 확인합니다.
캐시가 없는 상태는 자동 다운로드 가능 여부와 구분합니다. 인터넷 도달성·전체 오프라인 캐시·실제 게임 화면 진입을 검사한 것으로 표시하지 않습니다.

실행 기록은 세션을 구분해 기기에 남습니다. 최근 최대 128개, 파일 최대 128KiB이며 마지막 실패와 마지막 시작 검사도 보관합니다.
일반 상태 화면에는 최근 20개, 명시적인 진단 내보내기에는 전체 보관분을 포함합니다.
RPC 메서드·결과, HTTP 실패 종류·경로 지문, 시작 단계·오류 종류만 기록하며 인증 토큰·요청 본문·사용자 선택 파일 경로는 저장하지 않습니다.

기록 저장은 최대 초당 두 번으로 묶고 정상 종료와 시작 실패 때 마무리합니다.
강제 종료 직전 약 0.5초의 관측은 보장하지 못하며, 전원 장애 내구성 검사를 대신하지 않습니다.
기록 지우기는 계정·리소스·세션을 삭제하지 않습니다.

## 계정과 저장 슬롯

일반 계정은 `state.db`, 감상 계정은 `media-state.db`에 분리합니다.
기존 `sandbox` 자료를 유지하며 각 모드의 다음 시작 계정을 따로 선택합니다.

| 작업 | 동작 |
| --- | --- |
| 목록 | 일반/감상 계정을 구분하고 현재 실행 계정과 다음 시작 계정을 표시합니다. 계정 24개·복구 지점 16개씩 페이지를 이동합니다. |
| 생성 | 새 저장 슬롯에 실제 초기 계정을 준비합니다. 일반 계정과 명시적으로 선택한 전체 해금 감상 계정을 구분합니다. |
| 복제 | 모든 계정 저장값과 원본 protobuf 바이트를 새 슬롯으로 복제합니다. 게임 내 이름과 ID는 보존하는 **동일 계정의 분기**이며 새 공식 ID 발급이 아닙니다. |
| 선택 | 다음 서버 시작에 적용합니다. 게임을 이미 시작했다면 게임과 서버를 종료·재실행해야 합니다. 창만 닫아서는 바뀌지 않습니다. |
| 백업 | 계정 ZIP을 만들어 사용자가 고른 위치로 내보냅니다. |
| 가져오기 | ZIP의 종류·버전·스키마·전체 해시와 미리보기 내용을 검증한 뒤 새 슬롯 또는 명시한 기존 슬롯에 적용합니다. |
| 교체 | 현재 대상의 변경 지문을 다시 확인하고, 같은 SQLite 쓰기 트랜잭션 안에서 기존 자료의 복구 지점을 만든 뒤 교체합니다. |
| 복구 | 선택한 복구 지점의 계정·모드·내용을 확인하고 원래 저장값으로 되돌립니다. 복구 전 현재 값도 다시 보관합니다. |

로컬 계정 이름은 저장 슬롯의 이름이며 게임 내 매니저 이름과 별개입니다.
일반/감상 모드를 바꿔 다른 종류의 ZIP을 강제로 덮어쓰지 않습니다.
선택 기록이 손상됐거나 선택한 계정이 사라졌다면 다른 계정으로 조용히 바꾸지 않고 시작 오류로 표시합니다.

## 계정 ZIP에 들어가는 자료

대상 계정에 속한 다음 7개 테이블의 모든 행을 같은 SQLite 읽기 트랜잭션에서 캡처합니다.

- 프로필 식별자와 User.Get 스냅샷
- 게임 설정과 초기 계정 출처
- 레슨 진행 시계
- 설정 변경의 재시도 응답과 일반 라이브 시도 기록

원본 protobuf의 알 수 없는 필드도 바이트 그대로 보존합니다.
다른 계정의 자료와 로그인 세션은 포함하지 않습니다. 복원 시 대상 계정의 이전 세션만 무효화하며 다시 로그인합니다.
언어·그래픽 같은 서버 앱 전역 설정과 다운로드한 리소스 파일은 계정 백업에 포함되지 않습니다.

**계정 ZIP과 리소스 ZIP은 서로 다른 파일입니다.**
리소스 ZIP으로 계정을 복원하거나 계정 ZIP으로 게임 리소스를 가져올 수 없습니다.
Sideloadly·LiveContainer·SideStore·Android·Mac 사이 계정 이동도 같은 게임 스키마와 계정 종류의 ZIP을 사용하는 방식입니다. 실제 각 설치 도구의 Files 공급자 선택은 별도 기기 검증 범위입니다.

미리보기 사본이 바뀌거나 대상 계정이 미리보기 이후 수정되면 작업을 거절합니다.
저장 공간 부족이나 복구 지점 저장 실패가 발생하면 기존 계정을 먼저 덮어쓰지 않습니다.
활성 계정 교체·복원은 Android/Mac에서 서버를 중지한 상태에서 수행합니다. 통합 IPA는 게임 시작 전 처리하거나, 게임을 이미 시작했으면 완전히 종료 후 진행합니다.

## 관련 게임 기능 조사와 복구

이번 소스에서 새로 처리하는 게임 호출은 정확히 두 개입니다.

- `Profile.FindUser`: 선택된 로컬 계정의 실제 ID로 저장된 공개 프로필·보유 카드/사진·등급을 조회합니다.
- `Profile.UpdateBirthday`: 미등록 생일의 초기 등록과 동일 날짜 재시도를 지원합니다. 기존 생일 변경과 생일 이벤트·보상을 만들지 않습니다.

로컬 관리 화면의 생성·복제는 공식 Firebase 가입·재가입 호출의 복구가 아닙니다.
기존 설정 저장을 새로운 게임 RPC로 세지 않습니다.
[관련 원본 API 전체 조사](account-game-api-investigation.md)와 [프로필 복구 범위](profile-directory-support.md)를 참고하세요.
이 결과를 충분한 대량 게임 복구나 새 공개 릴리즈의 근거로 주장하지 않습니다.
