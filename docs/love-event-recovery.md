# 모시코이 로컬 복구와 이벤트 설정

현재 배포는 [2026.11.17.1](https://github.com/tagundo/IdolyPride_client/releases/tag/v2026.11.17.1)입니다. 6개 이벤트와 72편의 목록 중 원본 ADV가 없는 1편을 제외한 71편을 지원합니다.

아래는 구현 과정의 조사·검증 기록입니다. 배포 보류와 개인 검증용 전달 계획은 당시의 방침이며, 현재 실행 파일과 최종 자동 검증 범위는 위 날짜 릴리즈를 따릅니다. 실제 Unity 게임 재생과 공식 계정 인증을 검증한 것으로 표시하지 않습니다.

`もしも君と恋をしたら`(もし恋, 모시코이)는 일반 이벤트 스토리 목록과 별도의 `api.Love` 기능입니다. 원본 6.1.1 프로토콜에는 17개 RPC가 있습니다. 이번 작업은 서버 설정에서 콘텐츠를 선택하는 기능과 실제 계정별 플레이 상태를 함께 연결합니다. 공개 릴리즈는 보류하며, 이 문서는 실제 게임 검증 완료를 뜻하지 않습니다.

## 사큐×마호 입구

서버의 **콘텐츠 → 모시코이 설정**에서 `사큐×마호 ~KISS AND MAGIC!~`를 켜고 적용한 뒤, **게임 홈 → 이벤트 → 사큐×마호 배너**에서 엽니다. 일반 모시코이의 캐릭터 선택과는 입구가 다릅니다. 설정을 저장한 뒤 현재 적용에 반영되지 않았다면 서버를 다시 시작해야 합니다. 감상 계정은 별도 선택을 저장하지 않은 경우 여섯 이벤트를 모두 켭니다.

원본 Android 6.1.1 정적 분석에서 홈 이벤트 버튼은 `MenuButtonUtility.OnClickAsync` (`0x5250d48`)를 통해 `HomeEventInfo.EventCount` (`0x49ed0c0`)를 확인합니다. 이 값은 `loveEventInfos.Count`도 합산하고, 목록의 `AllInfos`는 해당 행을 열거합니다. 이벤트 목록 클릭 처리 (`0x55e74cc`)는 `baseType == 2`이면 행의 `id`를 `LoveExtraTitleTransitionParam.loveId`로 보내 Extra 타이틀을 엽니다. 현재 응답은 `love-extra-25-0426`, `baseType=2`, `limitedExtraTitleAssetId=love-25-0426`을 제공합니다. 무기한 표시의 `endTime=0`은 원본 `TimeManager.IsExpired` (`0x45d1e4c`)에서 만료로 처리되지 않습니다. 이 근거는 코드상의 진입 경로 확인이며 실제 기기 재생 검증과 구분합니다.

## 보존 자료와 확인 한계

원본 공개 마스터의 `LoveStoryEpisode` 72개, `LoveLevel` 57개, `LoveHomeAction` 243개, `LoveColor` 1개와 `Story`·`Setting`·`Item`을 사용합니다. 72개 에피소드는 재사용되는 파일을 포함한 ADV 69개에 대응합니다. 기존 보관본에는 이 중 68개가 있으며 `love_2411_04_02`의 원문은 확인 중입니다. 누락된 원문의 분기 검증을 완료한 것으로 표시하지 않습니다. 에피소드의 `rewardId`는 비어 있으므로 일반 스토리 읽기의 돌 보상을 붙이지 않습니다.

로컬 서버 ID는 `love-23-0514`, `love-23-1114`, `love-24-0517`, `love-24-1114`, `love-26-0313`, `love-extra-25-0426`입니다. Extra의 실제 에피소드·스토리 파일 이름은 서버 ID와 다른 원본 이름을 사용하므로 명시적으로 대응합니다.

참고 구현은 Solis `9b67c06939403d7035e1795745f791340a775868`입니다. 코드 복사와 별개로 참고 자료의 AGPL 고지·출처와 원본 게임 자료의 권리를 구분합니다. 참고 자료가 캡처에 근거한다고 밝힌 이벤트 정보와, 추론한 분기 점수·보너스를 구분합니다. 특히 일부 리오·Extra 경로와 엔딩 보너스는 공식 응답으로 독립 검증되지 않았습니다. 확인되지 않은 재화 보상이나 보너스를 공식 결과로 만들어 지급하지 않습니다.

[독립된 준비 검사](https://github.com/tagundo/IdolyPride_client/actions/runs/43834468002)는 공개 참조 파일 12개의 정확한 크기·SHA 및 라이선스 핀을 확인했습니다. 정규화 JSON은 44,247바이트, SHA-256 `3f1f8e30a499c630a23dfca8e9216e165a2086d3c031b52aba39dc76d05438ec`이며 작은 산출물을 다시 읽어 검증했습니다. 공식 계정 로그인은 수행하지 않았습니다.

## 서버 설정

`server-events.json`의 스키마 1은 `revision`과 `love_events` 배열을 저장합니다. 각 항목은 `event_id`, `start_time_ms`, `end_time_ms`만 가집니다. 지원 목록의 여러 이벤트를 동시에 선택할 수 있습니다. 기간은 명시적인 **로컬 서버 운영 기간**이며 원본 공식 기간의 복원이 아닙니다. 전역 시계는 바꾸지 않습니다. 원본 종료 시각·기간을 확인할 수 없으면 카탈로그에 null로 남깁니다.

설정 화면의 자동 저장은 설정 파일만 원자적으로 바꿉니다. 실행 중 게임은 시작 때 고정한 값을 사용하고, 변경값은 다음 서버 시작 때 적용합니다. 화면은 저장값과 현재 적용값을 구분합니다. 항목을 끄거나 기간을 바꾸어도 진행도를 삭제하거나 보상을 정산하지 않습니다. 미준비 카탈로그의 이벤트를 새로 활성화하지 않습니다.

Elichika v2026.11.14.1의 선택·예약·실행 상태 분리를 참고하지만, 전역 이벤트 하나를 바꾸면서 종료·보상·초기화하는 동작은 그대로 가져오지 않습니다. 아이프라의 Home은 여러 Love 이벤트와 다른 이벤트 종류를 함께 담습니다.

## 감상 모드와 계정 보존

감상 모드에서도 같은 ADV와 분기를 볼 수 있게 연결합니다. 감상용 진행·저장 슬롯은 감상용 데이터베이스와 선택된 프로필에만 저장하고 일반 계정을 열거나 수정하지 않습니다. 감상에서는 스토리의 재화·레벨 조건을 건너뛰며 실제 보유품이나 보상을 만들지 않습니다. 일반 모드의 비용·조건과 구분합니다.

`UserLove`의 원본 필드 네 개만으로 경험치·분기·시계·저장 슬롯을 표현할 수 없어, 별도의 `profile_love_progress` 테이블을 계정 스냅샷과 한 트랜잭션으로 갱신합니다. 백업 형식 2는 이 여덟 번째 테이블을 포함합니다. 기존 형식 1의 일곱 테이블 백업은 원래 해시를 먼저 검증한 뒤 추가 진행이 빈 상태로 가져옵니다. 덮어쓰기 전 복원점·CAS 및 일반/감상 모드 경계를 유지합니다.

공식 계정 가져오기나 과거 백업에 원본 `UserLove`가 있어도 누락된 서버 진행을 추정하거나 기존 엔딩을 조용히 초기화하지 않습니다. 초기 등록·재시작·초기화는 구별된 명시 동작입니다.

## 검증 상태

핵심 소스의 집중 검사 1,598개와 전체 검사 9,029개(168개 건너뜀·375개 하위 검사)가 `23f741c`에서 통과했습니다. 첫 실제 자료 생성 검사 42개도 통과했고, 기존 파일 554개를 보존한 197,160,108바이트 묶음과 5,702,787바이트 공개 오버레이를 만들었습니다. 작은 증빙과 오버레이의 전체 SHA를 별도로 다시 읽어 확인했습니다. 대형 묶음의 로컬 다운로드는 하지 않았으며 Native별 동일 SHA 재생성·포함 검증은 진행 중입니다. Love API·원본 마스터 카탈로그·계정 백업 형식 1/2·감상/일반 분리·세 플랫폼 설정 화면의 원격 검증이 끝나기 전에는 플레이 복구 완료 또는 배포 완료로 표시하지 않습니다. 별도 미션 수령과 확인되지 않은 보너스는 이 복구 결과와 구분해야 합니다.

공식 릴리즈는 만들지 않습니다. 최종 검증을 통과한 변경 실행 파일만 날짜 버전 `2026.11.16.2`를 붙여 개인 검증용 CI 아티팩트로 전달합니다.
