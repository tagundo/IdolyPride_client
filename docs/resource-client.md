# Android 로컬 리소스 클라이언트

`아이프라 로컬 리소스`는 기존 로컬 클라이언트 옆에 설치하는 별도 앱입니다.
패키지는 `game.qualiarts.idolypride.local.resources`입니다. 기존 게임을 삭제하거나
기존 앱의 데이터를 덮어쓰지 않습니다. 로컬 서버에 저장된 프로필을 사용하며,
게임 설정과 리소스 캐시는 새 앱에 별도로 생성됩니다.

게임 연결 주소는 `http://127.0.0.1:50051`, Octo 리소스 주소는
`http://127.0.0.1:8080/`입니다. 대응하는 리소스 게이트웨이가 포함된 서버가 필요합니다.
이 문서는 빌드 구성을 설명하며, 게시되지 않은 APK의 다운로드 링크를 제공하지 않습니다.

## 빌드와 검증

`tools/package_android_resource_client.py`는 검증된 일본판 6.1.1 원본 병합 APK에서
SDK DEX와 게임 리소스를 가져옵니다. 기존 일반 로컬 클라이언트와 일치하는
`libil2cpp.so`의 여섯 가지 로컬 로그인 부트스트랩 변경을 재사용합니다.
UI 진단 제공자, 추가 DEX, 소프트웨어 AES, 결제 우회나 새 네이티브 훅을 추가하지 않습니다.

로컬 HTTP 연결을 위해 원본 `globalgamemanagers`의 Unity
`PlayerSettings.insecureHttpOption`을 `NotAllowed(0)`에서 `AlwaysAllowed(2)`로
변경합니다. 고정된 6.1.1 파일 해시·길이·형식을 확인한 뒤 독립 분석에서 확인한
한 필드만 바꾸며, 실제 변경은 한 바이트입니다. Android의 HTTP 허용 호스트는
기존의 `127.0.0.1`로 유지합니다. SDK 초기화·성공 플래그나 TLS 검증을 바꾸는
수정이 아닙니다. 원본의 HTTP 금지 정책이 남아 있던 앞선 후보에서는 실제
게임의 `E203`과 로컬 리소스 서버에 SDK 요청이 도착하지 않는 현상을 관측했습니다.

메타데이터를 바꿀 때는 `assets/bin/Data/unity_app_guid`도 새 코드 자료의
해시로 결정한 UUID로 갱신합니다. 원본 Unity 엔진은 이 값과 외부
`il2cpp/unity.ver`를 비교해 코드 자료를 다시 추출합니다. 이 값을 유지한
이전 QA 업데이트에서는 실행 중인 프로세스가 APK의 수정본 대신 이전
메타데이터 캐시를 매핑하는 것을 확인했습니다. 동일한 입력으로 빌드하면
같은 UUID를 사용합니다. 계정·저장 데이터, `productGUID`, SDK 초기화
플래그와 별개의 Unity 코드 캐시 버전이며, 실제 재추출 검증은 진행 중입니다.

매니페스트와 리소스 XML은 고정된 원본 APK의 매니페스트·ARSC·`res/**`만 담은
작은 APK에서 새로 디코딩합니다. 전체 게임 실행 파일을 다시 디코딩하지 않습니다.
패키지·권한·provider authority·리소스 패키지 이름을 함께 바꾸고,
루프백 HTTP 허용 범위를 유지합니다. 원본 리소스 ID와 이름, 나머지 APK 멤버 해시를 검증합니다.
이번 APK의 독립 비교에서는 리소스 값·구성·ID·이름이 모두 보존됐으며,
APKEditor가 ARSC의 속성 604개와 ID 451개의 가시성 표시를 `PUBLIC`으로 정규화한 것도 확인했습니다.

서명에는 기존의 비공개 `data/client-signing/local-client.p12`와
`data/client-signing/local-client.password`를 사용합니다. 비밀번호 값은 Python으로
읽거나 출력하지 않고 `keytool -storepass:file`과 `apksigner --ks-pass file:`로 전달합니다.
한 줄짜리 비밀번호 파일을 두 번 소비하지 않도록 PKCS12 키 암호는 저장소 암호를 재사용합니다.

이 새 패키지의 고정 인증서 SHA-256은
`3c56abcfd37697c4a1436849391a2002793df18082d2843130a7e99292a5bd6c`입니다.
이 키를 유지하면 새 패키지의 다음 버전을 같은 서명으로 만들 수 있습니다.
이전 공개 `game.qualiarts.idolypride.local` 클라이언트의 인증서
`86fbcf5674eb086f74a95756d68a8db52e203b418d3874b440ecabdf259d6a81`과는 다르므로,
기존 앱을 직접 업데이트하는 APK로 취급하지 않습니다.

빌드 도구는 입력 APK·일반 네이티브 기준의 해시, 인증서, ARM64 구성,
새 패키지·표시 이름, APK 멤버 변경 목록과 16KB 정렬을 검증한 뒤 증거 JSON을 만듭니다.
기존 APK·출력 파일은 덮어쓰지 않으며, 설치·데이터 이전·릴리스 게시를 수행하지 않습니다.
서명 및 정적 검증은 실제 기기에서의 게임 진행 검증과 별개입니다.
