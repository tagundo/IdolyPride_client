# 같은 기기에서 로컬 게임·서버 앱 실행

[릴리스](https://github.com/tagundo/IdolyPride_client/releases)에서 환경에 맞는 파일을 받습니다. **Android는 서버 APK와 게임 APK 하나를 같은 기기에 설치하고, iPhone·iPad와 Mac/PlayCover는 같은 서버·게임 통합 IPA 하나를 설치합니다.** 터미널·Python·Termux 없이 앱의 버튼으로 실행합니다. 현재 공개 파일과 버전은 [README](../README.md#앱으로-실행하기)를 확인합니다. 아래의 Android v0.3.0 진단 기록은 당시 동작과 수정 이력입니다.

다음은 [v0.3.0 베타](https://github.com/tagundo/IdolyPride_client/releases/tag/local-server-v0.3.0) 당시의 기록입니다. 당시 사용자 Android 기기에서 로컬 로그인·홈과 캐릭터 표시·편성·초기 튜토리얼 전체 진행을 확인했으며, 일반 라이브 플레이와 PlayCover 게임의 화면 진행 검증은 남아 있었습니다. 현재 다운로드 파일과 검증 범위는 위 README와 해당 릴리즈 기록을 확인합니다.

## Android

서버 앱은 Android 8 이상, 게임은 Android 9 이상의 ARM64 기기가 필요합니다. 릴리스에서 다음 두 파일을 받습니다.

| 파일 | 용도 |
| --- | --- |
| `IdolyPride-Local-Server-Android.apk` | 서버 v0.3.0 앱, 표시 이름 **아이프라 서버** |
| `IdolyPride-6.1.1-Local-Android.apk` | 게임 클라이언트, 표시 이름 **아이프라 로컬** |

1. 파일 앱에서 두 APK를 설치합니다. 필요한 경우 해당 파일 앱의 APK 설치 권한을 허용합니다.
2. **아이프라 서버**를 열고 **서버 시작**을 누릅니다. 첫 실행에는 앱에 포함된 서버 데이터를 준비합니다.
3. **실행 중**으로 바뀌면 **아이프라 로컬 실행**을 누릅니다. 서버 실행 알림을 유지한 채 게임을 사용합니다.
4. 끝나면 서버 앱에서 **서버 중지**를 누릅니다. Android가 백그라운드 앱을 종료했다면 서버 앱을 다시 열어 시작합니다.

서버 패키지는 `game.qualiarts.idolypride.localserver`, 게임 패키지는 `game.qualiarts.idolypride.local`입니다. 기존 공식 게임과 별도로 설치하며 공식 계정이 자동으로 옮겨지지는 않습니다.

서버 개발 APK는 고정된 **공개 개발 서명**을 사용합니다. 같은 서명의 후속 APK를 업데이트 설치하면 앱 전용 저장소의 DB가 유지됩니다. **업데이트하려고 기존 서버 앱을 먼저 삭제하지 마세요. 앱 삭제나 설정의 데이터 지우기는 프로필·진행 DB를 삭제합니다.**

### v0.2.0의 인증 오류 수정

게임 제목 화면에서 `Unauthenticated`가 표시되고 서버 기록에 `Refund/GetTerm → UNAUTHENTICATED`가 나온다면 **서버 앱만 v0.3.0으로 업데이트**합니다. 이 호출은 로그인 전의 환불 기간 조회입니다. 기존 아이프라 로컬 게임 APK는 그대로 사용하며, 서버 앱을 삭제하거나 데이터를 지울 필요가 없습니다.

### 홈 API 성공 뒤 로딩 화면이 유지될 때

`Home.Enter → OK`는 서버 응답 성공이며 화면 표시 성공을 뜻하지 않습니다. v0.2.3부터 게임 내부에서 관측된 예외와 셰이더 대기 상태를 서버 앱에 표시합니다.

`NullReferenceException @ Solis.OutGame.HomeOfficeActors.CreateActorDescriptor`가 표시되면 **서버 v0.3.0으로 업데이트**합니다. 홈 배경은 기본 캐릭터 17명 중에서 인물을 선택하지만 구형 로컬 초기 데이터에는 5명만 있어 조회가 실패할 수 있었습니다. 업데이트 후 서버 시작 시 이전 서버의 초기 구성으로 인식되는 프로필에 누락된 기본 캐릭터·외형만 추가합니다. 이 로스터 보완은 진행·설정·세션을 유지하며 카드나 잠금 캐릭터를 지급하지 않습니다. 가져온 계정 데이터는 자동 보정에서 제외합니다.

**게임을 강제 종료한 뒤 서버를 업데이트하고, 서버 시작 → 게임 실행 순서로 다시 엽니다.** 실행 중인 게임에는 이전 5명 목록이 메모리에 남아 있을 수 있습니다. 앱 삭제나 데이터 지우기는 필요하지 않습니다. 상태·최근 예외 문구는 길게 눌러 선택·복사할 수 있습니다.

1. [서버 v0.3.0](https://github.com/tagundo/IdolyPride_client/releases/tag/local-server-v0.3.0)의 APK를 기존 서버 앱 위에 업데이트 설치합니다.
2. [진단 게임 v0.2.1](https://github.com/tagundo/IdolyPride_client/releases/tag/local-diagnostics-v0.2.1)의 `IdolyPride-Local-Diagnostic-Android-arm64.apk`를 설치합니다. 별도 **아이프라 진단** 앱이 추가되며 기존 로컬 게임을 삭제하지 않습니다.
3. 서버를 시작한 뒤 **진단 게임 실행**을 누르고 로딩을 재현합니다.
4. 서버 앱으로 돌아와 **게임 로딩 상태**와 **최근 게임 예외**를 확인합니다. **진단 기록 내보내기**를 누르면 Android 파일 저장 화면으로 JSON을 저장합니다.

게임 예외는 종류와 메서드 이름만 수집합니다. 계정·토큰·로그 원문·DB는 진단 파일에 포함하지 않습니다. 진단 게임이 로그를 남기지 않는 대기는 기록되지 않을 수 있습니다. 수집은 게임 프로세스 시작 후 30분으로 제한합니다. 제한 시간 후 다시 수집하려면 Android 설정에서 **아이프라 진단 → 강제 종료**한 뒤 다시 엽니다. 데이터 지우기는 필요하지 않습니다.

### 라이브 목록 오류와 기본 홈 캐릭터 배치

`Quest/Top → UNIMPLEMENTED`가 기록되면 서버 v0.3.0으로 업데이트합니다. v0.2.7부터 `Quest.Top`과 `Quest.ListMain`에서 실제 마스터·저장 진행도에 따른 메인 라이브 목록을 제공합니다. 첫 메인 퀘스트의 실험 기능 밖에 있는 전투 시작·결과 계산은 아직 지원하지 않습니다.

구형 기본 프로필은 홈 4곳에 같은 아이돌을 지정해 각 화면의 로딩 작업이 같은 3D 객체의 위치·표시 상태를 바꿀 수 있었습니다. v0.2.7은 이 정확한 기본 중복 배치만 보정하며 기본 홈의 캐릭터와 저장된 설정·튜토리얼·세션을 유지합니다. 가져온 계정이나 직접 바꾼 배치는 자동 변경하지 않습니다. 게임을 강제 종료한 뒤 서버를 업데이트·시작하고 다시 실행합니다. 진단 게임 v0.2.1은 그대로 사용합니다.

### 라이브 버튼 뒤 참조 오류가 기록될 때

`Quest.Top → OK` 뒤 `NullReferenceException @ Solis.OutGame.LiveTopScreenPresenter.RequestLiveProgressAsync`가 있으면 서버 v0.3.0으로 업데이트합니다. 라이브 메뉴가 필수로 읽는 하이스코어 지역 정보가 빠진 문제를 수정했습니다. 하이스코어 지역은 실제 목록·기존 기록을 제공하되 플레이는 잠겨 있습니다. 미완료 GameStart에는 실제 튜토리얼 목록도 제공합니다.

이 메뉴 오류와 라이브 전투 미구현은 별개입니다. 첫 메인 퀘스트의 실험 기능 밖에 있는 전투 시작·결과 계산은 아직 지원하지 않습니다. 진단 게임을 강제 종료하고 서버 앱만 업데이트한 뒤 다시 실행해 확인합니다. 저장 데이터와 진단 게임 v0.2.1은 유지합니다.

### 튜토리얼 손가락이 빈 시작 버튼 위치를 가리킬 때

서버 v0.2.9는 구형 로컬 기본 계정의 누락된 초기 카드·아이템과 5인 편성을 보완합니다. 다섯 자리에 보유 카드가 있어야 게임이 시작 버튼을 표시합니다. 알려진 초기 상태인 경우에만 한 번 적용하며 이름·홈·설정·세션·튜토리얼 진행은 유지합니다. 게임을 강제 종료하고 서버 APK만 업데이트·시작한 뒤 기존 진단 게임 v0.2.1로 확인합니다. 앱 삭제나 데이터 초기화는 필요하지 않습니다.

이 초기 편성 보완은 v0.2.9의 수정이며 현재 v0.3.0에도 포함됩니다. 현재 배포본은 원본 튜토리얼 기록 재생도 제공하며, 첫 메인 퀘스트의 실험 기능 밖에 있는 일반 라이브 계산·정산은 미지원입니다.

### 시작 버튼 뒤 리소스 목록 오류가 뜰 때

`Quest/ListAsset → UNIMPLEMENTED`가 기록되면 서버 v0.3.0으로 업데이트합니다. 이 API는 현재 덱 5명의 캐릭터·의상·헤어 ID를 돌려줘 게임이 라이브 리소스를 준비할 수 있게 합니다. 게임을 강제 종료하고 서버 앱만 업데이트·시작한 뒤 기존 진단 게임 v0.2.1로 실행합니다. 별도의 게임 APK 교체나 계정 초기화는 필요하지 않습니다.

현재 배포본은 튜토리얼 원본 재생을 제공하며, 첫 메인 퀘스트의 실험 기능 밖에 있는 일반 라이브 계산·정산은 미지원입니다.

### 리소스 준비 뒤 튜토리얼 라이브에서 멈출 때

`Tutorial/StartQuest → UNIMPLEMENTED`가 기록되면 서버 v0.3.0으로 업데이트합니다. 이 버전은 원본 short/full 튜토리얼 기록을 재생하고 시연 편성과 추가 출연자 리소스를 함께 준비합니다. **시연은 원본 기록의 편성이며 저장된 덱으로 새 전투를 계산하지 않습니다.** 라이브 재생 요청 자체는 카드·재화·덱을 변경하지 않습니다. 이어지는 레슨 보상·강화·유닛 편성 요청은 별도로 저장하며, 첫 메인 퀘스트의 실험 기능 밖에 있는 일반 라이브 계산과 보상은 미지원입니다.

게임을 강제 종료하고 서버 앱만 업데이트·시작한 뒤 기존 진단 게임 v0.2.1로 실행합니다. 게임 APK 재설치나 계정 초기화는 필요하지 않습니다. 원본 튜토리얼 라이브 재생은 Android 기기에서 확인했습니다.

### 튜토리얼 라이브 뒤 레슨 보상에서 멈출 때

`Tutorial/ReceiveLessonReward → UNIMPLEMENTED`는 서버 v0.2.12에서 수정했습니다. 레슨 보상 1회 지급·카드 강화·새 유닛 생성과 사쿠라 메시지의 선택 저장/완료까지 처리합니다. 기존 게임을 강제 종료하고 서버 APK만 업데이트한 뒤 다시 실행합니다. 저장된 튜토리얼 단계부터 이어가며 앱 삭제나 데이터 초기화는 필요하지 않습니다. Android 사용자 기기에서 이 후반 구간을 포함한 초기 튜토리얼 완료와 홈 재접속을 확인했습니다.

### 예외가 없고 수집 시작만 표시될 때

서버 v0.3.0과 진단 게임 v0.2.1을 사용합니다. 새 진단판은 검증된 6.1.1 코드 위치에서 홈 환경·배경·캐릭터·셰이더·표시 전환의 고정 단계만 기록합니다. **마지막 단계**는 해당 코드가 실행됐다는 관측이며 화면 표시 성공이나 작업 완료를 보증하지 않습니다. 네이티브 단계 추적을 사용할 수 없으면 그 상태를 표시하고 게임을 계속 실행합니다.

**게임 전체 네트워크**는 게임 앱 UID의 실제 누적 수신·송신량을 5초 간격으로 읽습니다. SDK 등 같은 앱의 통신도 포함하며 리소스 다운로드 전용 수치나 완료율이 아닙니다. 서버의 마스터 전송량과 별도로 표시합니다. 계정 값·주소·로그 원문은 수집하지 않습니다.

서버와 진단 APK를 모두 업데이트한 뒤 게임을 강제 종료하고 다시 실행합니다. 재현 후 **마지막 단계**, **게임 전체 네트워크** 또는 내보낸 진단 JSON으로 대기 구간을 확인합니다. 구형 서버는 새 이벤트를 처리하지 못하므로 서버 앱 버전도 확인합니다.

**마스터 파일 전송**은 같은 기기의 서버가 실제 보낸 바이트와 완료 건수입니다. 모델·음성 등 Octo 리소스는 별도 경로를 사용하므로 이 수치로 전체 게임 다운로드 완료를 판단하지 않습니다. 원래 게임의 다운로드 UI가 나타나지 않는 원인은 계속 조사 중입니다.

## Mac + PlayCover

Apple Silicon Mac과 PlayCover가 필요합니다. iPhone·iPad와 같은 **서버·게임 통합 IPA 하나**를 받습니다. 새 날짜 버전의 파일명은 `IdolyPride-<날짜버전>-Unified-iOS.ipa`이며, 현재 공개 v0.3.35의 이름은 `IdolyPride-6.1.1-Unified-iOS.ipa`입니다. 다음 릴리즈에는 별도 Mac 서버 앱과 별도 PlayCover IPA를 포함하지 않습니다.

1. 기존 별도 Mac 서버를 사용했다면 완전히 종료합니다.
2. PlayCover 앱 목록에서 통합 IPA를 가져와 설치·재서명합니다.
3. 설치한 **아이프라 로컬**을 실행합니다. 앱 안에 서버가 포함되며 서버 메뉴가 먼저 열립니다.
4. 사용할 언어를 선택하고 서버 준비가 끝나면 **게임 시작**을 누릅니다. 게임과 서버는 같은 앱에서 실행됩니다.
5. 게임 중에는 오른쪽 위를 **2초간 길게 눌러** 서버 메뉴를 엽니다. Mac의 **로컬 서버 설정… / ⌘⇧,**도 사용할 수 있습니다.

계정·설정은 통합 IPA의 앱 컨테이너 안 `Library/Application Support/IdolyPrideLocal`에 저장됩니다. 앱 삭제 전에 필요한 계정 ZIP과 리소스 ZIP을 각각 내보냅니다. 리소스 ZIP에는 계정이 포함되지 않습니다. 이전 별도 Mac 서버의 `~/Library/Application Support/IdolyPrideLocal`과는 저장 위치가 다르며 자동 이전되지 않습니다. [통합 IPA 안내](../ios-unified/README.md)와 [계정 ZIP 안내](server-user-management.md)를 참고합니다.

## 포함된 데이터와 저장 상태

Android 서버 앱과 통합 IPA의 내장 서버는 게임 API `127.0.0.1:50051`, 마스터 파일 `127.0.0.1:8080`을 사용합니다. `127.0.0.1`은 게임을 실행하는 기기 자체입니다. 같은 포트의 소스 서버나 Termux 서버를 함께 실행하지 않습니다.

v0.3.0에는 6.1.1 스키마, 원본 암호화 마스터 202개, 시작 데이터용 JSON, 공개 약관·도움말 응답 10개와 공개 튜토리얼 재생·스토리 기본 목록이 포함됩니다. 첫 실행은 이 공개 데이터를 준비하며 공식 로그인이나 계정 수집을 실행하지 않습니다. 모델·음성·영상 등의 전체 Octo 리소스가 포함된 것은 아닙니다. 위 진단 게임과 서버 상태 UI는 Android용입니다.

새 `sandbox` 프로필은 홈 배경의 일반 캐릭터 17명과 검증한 기본·라이브 의상·헤어, 레벨 1 매니저, 초기 카드 17장·촬영 아이템 1개·레슨 피스 100개와 5인 기본 편성을 준비합니다. 원본 초기 보상 정의에 근거한 로컬 생성 데이터이며 전투 보상·튜토리얼 완료·조건부 캐릭터 해금은 생성하지 않습니다. 알려진 구형 빈 계정은 해당 초기 누락분만 보완하고 기존 진행은 유지합니다. 명시적으로 가져온 snapshot은 자동 보정하지 않습니다.

배포된 v0.3.0의 지원 범위는 다음과 같습니다.

| 기능 | 지원 범위 |
| --- | --- |
| 홈·설정·튜토리얼 | 로그인·진입·리뷰·캐릭터 배치와 초기화·진행·스킵 저장 |
| 라이브 목록·튜토리얼 시연 | 메인 목록과 5인 덱 리소스 조회, 원본 short/full 기록 재생 |
| 초기 튜토리얼 후반 | 레슨 보상 1회, 초기 형태 카드 강화, 새 유닛 생성, 사쿠라 메시지 선택·완료 |
| 덱 편집 | 새 번호 발급·수동 편집·삭제와 클라이언트가 자동 선택한 편성 저장; 서버의 자동 편성 계산·버디 대여는 미지원 |

| 선물함·친구 | 비어 있는 로컬 목록 조회; 선물 수령·친구 관계 변경은 미지원 |

| 카드 레벨 미션 | 검증된 한 미션의 목록·진행도 저장; 보상 수령은 미지원 |

상태 변경은 SQLite 트랜잭션으로 저장하며 기존 설정·세션·관련 없는 계정 데이터를 보존합니다. 첫 메인 라이브 실험 범위 밖의 일반 라이브 계산·정산, 확장 카드 육성, 가챠·구매 등은 v0.3.0에서 지원하지 않습니다. 구현이나 fixture가 없는 요청은 `UNIMPLEMENTED`입니다. 자세한 조건은 [게임 상태 구현 문서](gameplay-status.md)를 참고합니다.

**v0.3.0 베타에는 [첫 메인 라이브 실험 기능](first-live-support.md)이 포함됩니다.** 기본값은 꺼짐이며 서버를 중지한 뒤 해당 옵션을 선택해 시작합니다. 첫 메인 퀘스트만 로컬 규칙으로 계산하고 공식 점수 일치는 검증되지 않았습니다. 실제 게임의 일반 라이브 재생·결과 화면 검증은 남아 있습니다.

| 데이터 | Android 서버 앱 | 통합 IPA / PlayCover |
| --- | --- | --- |
| 상태 DB | 앱 전용 `files/data/state.db` | 앱 컨테이너 `Library/Application Support/IdolyPrideLocal/state.db` |
| 공개 스키마·마스터·JSON | 앱 전용 `files/data/` 아래 | 위 앱 컨테이너의 데이터 폴더 아래 |
| 앱 업데이트 | 같은 서명으로 설치하면 DB 유지 | 같은 앱의 컨테이너를 유지하는 업데이트 사용 |
| 앱 삭제 | 앱 데이터도 삭제 | 컨테이너가 삭제될 수 있으므로 먼저 계정·리소스 내보내기 |

서버 앱에는 공식 계정 인증정보가 없습니다. 기존 계정의 snapshot·응답·PlayCover Firebase archive를 보존하는 개발 도구는 [README의 계정 보존 절차](../README.md#로그인된-공식-세션에서-보존)를 참고합니다. Firebase archive는 현재 게임 세션 metadata와 다르며 새 로컬 앱이 공식 계정을 자동 복원하지 않습니다. archive·토큰·세션 파일을 채팅이나 공개 저장소에 올리지 않습니다.

## 패치·검증 범위

연결용 게임 클라이언트는 원본 API 문자열을 로컬 주소로 바꾸고, 검증된 6.1.1 native 바이너리의 6개 진입점을 패치합니다. Seed 초기화·갱신과 Firebase ID token 취득을 완료된 UniTask로 대체하고 기존 사용자 검사를 통과시킵니다. 대체 문자열은 서버가 무시하는 로컬 식별자이며 실제 인증정보를 읽지 않습니다. `Auth.Login` RPC는 유지해 로컬 서버에서 새 세션을 받습니다.

ARM64 스텁은 원본 해시·진입 바이트를 검사하며 Unicorn에서 반환 구조·레지스터·스택 보존을 실행 검증했습니다. Android 게임 APK의 서명·16KiB 정렬도 확인했습니다. native 코드 분석에서 `http` 주소가 `YetAnotherHttpHandler.Http2Only`를 설정하는 h2c 경로와 `https` 전용 인증서 분기를 확인했습니다. 실제 사용자 Android 기기에서 로컬 로그인·홈과 캐릭터 표시·편성·초기 튜토리얼 완료를 확인했습니다. 별도 자동 점검의 화면·요청과 한계는 [실제 게임 자동 점검](actual-game-qa.md)에 정리했습니다.

Mac/PlayCover는 통합 IPA의 내장 서버를 사용합니다. Apple SDK·Simulator 검증과 PlayCover·iPhone·iPad에서의 실제 Unity 게임 실행 검증은 별개이며, 실제 기기의 일반 라이브 플레이 검증 범위는 각 릴리즈 기록을 확인합니다.

Firebase Analytics·푸시 알림·구매 SDK 호출과 Octo 리소스 경로는 남아 있습니다. 현재 패치는 인증 부팅의 온라인 의존성을 줄이며 완전한 네트워크 격리나 전체 게임 플레이를 보장하지 않습니다.

Android 서버의 공개 개발 키와 게임 클라이언트의 서명 키는 별개입니다. 게임 APK를 직접 다시 빌드한다면 `data/client-signing/local-client.p12`와 `local-client.password`를 보존해야 같은 서명으로 업데이트할 수 있습니다. 기존 게임 클라이언트의 초기 CI 빌드는 임시 개발 키를 사용하므로 임의 재빌드 APK와 업데이트 호환을 가정하지 않습니다. PlayCover용 IPA는 PlayCover가 재서명합니다.

## 개발용 소스·Termux 실행

아래는 서버 코드를 개발하거나 별도 데이터 경로를 사용하는 경우의 선택 절차입니다. 배포 서버 앱과 동시에 실행하지 않습니다. 소스 실행의 기본 DB는 저장소의 `data/state.db`이며 서버 앱의 DB와 자동 공유하지 않습니다.

Mac에서는 Python 3.12 이상을 먼저 설치하고 저장소 루트에서 실행합니다. 스크립트는 macOS에 Python을 자동 설치하지 않습니다.

```sh
bash tools/setup_local_server.sh
.venv/bin/python tools/run_local_server.py \
  --client "$HOME/Downloads/game.qualiarts.idolypride-6.1.1-Decrypted.ipa" \
  --download-master
```

Termux에서는 저장소를 준비한 뒤 다음을 실행합니다.

```sh
bash tools/setup_local_server.sh
termux-setup-storage
.venv/bin/python tools/run_local_server.py \
  --client "$HOME/storage/downloads/idolypride-6.1.1.xapk" \
  --download-master
```

Termux 설치 스크립트는 `python`, `python-grpcio`, `capstone`, `clang`, `make`를 설치하고 `--system-site-packages` venv로 Termux의 grpcio를 사용합니다. Capstone binding·PyCryptodome 빌드가 필요할 수 있으며 실제 Termux 설치 완료는 미검증입니다.

`--client`는 스키마가 없을 때만 읽고, 외부 마스터 다운로드는 명시한 `--download-master`에서만 실행합니다. 새 데이터 경로에는 원본 클라이언트 파일 또는 준비된 ServerData가 필요합니다. 첫 준비 이후에는 `.venv/bin/python tools/run_local_server.py`로 실행합니다. 종료는 `Ctrl+C`입니다.

소스 helper는 기존 snapshot·세션·fixture를 보존하고 최소 신규 프로필을 만듭니다. 앱의 마스터 기반 시작 캐릭터 초기화와는 별도 경로입니다. `--data-dir /path/to/data --profile restored`로 데이터를 선택할 수 있고 `--manager-name`은 신규 프로필에만 적용됩니다. 전체 CLI·스키마 추출·fixture·마스터 준비는 [README 개발 절차](../README.md#개발용-소스-실행)를 참고합니다.
