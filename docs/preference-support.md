# 포토 이름과 프로필 레이아웃

현재 소스는 원본 6.1.1 계약을 사용하는 두 가지 로컬 설정 저장을 처리합니다.

이 코드는 현재 소스와 로컬 빌드한 미게시 Android v0.3.3 후보에 포함됩니다. [배포된 Android 서버 APK v0.3.2](https://github.com/tagundo/IdolyPride_client/releases/download/local-server-v0.3.2/IdolyPride-Local-Server-Android.apk)와 Mac 서버 앱 v0.3.2에는 이 두 기능이 없습니다. v0.3.3 후보는 GitHub 자산 업로드의 `401 Bad credentials` 오류로 릴리스에 게시하지 않았습니다. 이미지 트레이닝·VENUS의 자료 읽기 모듈도 후보에 포함되지만 기존 40개 디코딩 JSON 마스터 묶음에는 이벤트 읽기에 필요한 추가 테이블이 없고 개인 자료 가져오기 UI도 없습니다. 실제 이벤트 읽기는 보존한 개인 자료와 일치하는 추가 마스터를 준비한 별도 소스 환경이 필요합니다.

| 기능 | RPC 요청 | 변경하는 기존 보유 데이터 |
| --- | --- | --- |
| 포토 이름 | `Photo.Update`: `photoId` 문자열 필드 1, `name` 문자열 필드 2 | 해당 계정 `UserPhoto.name`만 변경 |
| 프로필 레이아웃 | `Profile.UpdateLayout`: `layoutType` 열거형 필드 1, `informationType` 열거형 필드 2, `colorType` 열거형 필드 3 | 기존 `UserProfile`의 해당 세 필드만 변경 |

두 응답은 `commonResponse` 필드 9999로 저장 후의 전체 포토 행 또는 프로필 행을 반환합니다. `PhotoNames(schema, state, profile)`와 `ProfileLayout(schema, state, profile)`의 `handle(path, plain)`을 공통 Application에서 호출하며, 인증은 기존 Application이 처리합니다. 이 모듈은 공식 서버에 접속하지 않습니다.

포토 이름은 원본 `PhotoDetailScreenPresenter`의 이름 변경 경로(`0x593a8d0`)에서 `ValidateText(name, 12, true)`를 호출하는 것과 같은 길이·공백·문자 조건을 사용합니다. 1~12 UTF-16 코드 단위이고 공백만으로 된 이름과 서로게이트 문자(보조 평면 문자의 쌍 포함)를 거절합니다. 원본의 `IsSurrogateText`(`0x46a6d94`, 문자 검사 `0x46a6e58`)는 서로게이트 외에도 유니코드 범주 `Mn`·`Mc`·`Me`·`So`와 정규식 `[☀-⛿]`의 U+2600~U+26FF 범위를 거절합니다. 따라서 결합 악센트·일부 기호도 허용하지 않으며, 이미 조합된 한글·일본어 등의 일반 문자는 보존합니다. 직접 들어온 CR/LF/탭은 기존 로컬 이름 입력 정책에 맞춰 거절합니다. 허용된 앞뒤 공백이나 문자를 자르거나 정규화하지 않습니다. 이름은 실제 보유한 포토에만 저장하며, 잠금·즐겨찾기·Dream 베이스인 포토도 이름만 바꿉니다. 공식 금칙어 검사나 서버의 정규화 정책까지 재현했다는 뜻은 아닙니다.

레이아웃은 원본의 `ProfileTopScreenPresenter.UpdateLayoutAsync`(`0x4331a7c`)와 요청 래퍼(`0x474cad0`)가 보내는 세 열거형을 사용합니다. 각 필드는 1~4의 정의된 값만 받습니다. 0(Unknown)이나 정의되지 않은 값은 저장하지 않습니다. 배경 포토·일러스트·즐겨찾기·자기소개·장식·엠블럼은 이 동작에서 변경하지 않습니다.

저장은 `State.mutate_snapshot`의 하나의 트랜잭션에서 수행합니다. 스냅샷·스키마·기존 사용자/프로필·보유 포토가 없거나 손상되었으면 부분 저장 없이 거절합니다. 같은 요청을 다시 보내면 현재 행을 응답하고 기존 원본 스냅샷 바이트를 유지합니다. 알 수 없는 protobuf 필드, 다른 보유 데이터, 계정 식별자, 세션, 다른 프로필과 레슨 시계도 유지합니다. 포토를 새로 만들거나 재화·능력치·미션·보상을 변경하지 않습니다.

개인 Dream 카탈로그는 전체 포토 바이트와 수집 당시의 보유 상태를 대조하므로 포토 이름을 변경한 뒤에는 예전 카탈로그를 그대로 재생하지 않습니다. 자동으로 해시를 다시 연결하거나 과거 진행을 새 상태로 간주하지 않습니다.

소스 검사 3,410개 통과·9개 생략에는 실제 6.1.1 protobuf 계약과 로컬 저장·재시도·재시작·동시 변경 경계 검사가 포함됩니다. 미게시 Android v0.3.3 후보는 기존 DB 보존 업데이트·서버 시작과 네이티브 암호화 통신의 로그인·사용자 조회를 확인했습니다. `Photo.Update`의 빈 ID는 `INVALID_ARGUMENT`, 보유하지 않은 ID는 `PERMISSION_DENIED`로 거절하고 사용자 조회 원본 바이트를 유지했습니다. 검사 프로필의 보유 포토는 0개이고 기존 레이아웃 값 일부가 정의되지 않아, 실제 이름 변경과 레이아웃 변경·원복은 검사하지 않았습니다. 이 두 RPC의 공식 응답 캡처나 실제 게임 설정 화면 동작까지 확인한 기능으로 표현하지 않습니다. `Photo.SwitchLock`과 카드 일러스트 선택은 이 구현에 포함하지 않습니다.
