# 프로필·카드·포토 설정

새 소스의 [로컬 공개 프로필 조회·초기 생일 등록 범위](profile-directory-support.md)는 별도로 기록합니다. 기존 등록 생일 변경·원격 유저 검색·생일 캠페인/보상은 포함하지 않습니다.

v0.3.34는 포토 정리부터 프로필 배경·장식·버디 카드·일러스트 선택까지 연결된 설정 저장을 묶습니다. [성공한 Actions 실행](https://github.com/tagundo/IdolyPride_client/actions/runs/43722420006)의 소스는 `4bf0325d90ac36c9f3a5a9f10c55ef7d0e456118`이며, 전체 7,271개·하위 375개 및 원본 자료 필수 검사 3개를 통과했습니다. [다운로드·검증 범위·해시](releases/recovery-v0.3.34.md)를 확인하세요. 실제 기기 편집 화면 검증과 서버 계약 검증은 구분합니다.

## 사용할 수 있는 흐름

1. 보유 포토의 이름을 바꾸고, 선택한 포토의 잠금 상태를 전환합니다. 여러 포토를 선택한 요청도 전체 소유권을 확인한 뒤 한 번에 처리합니다.
2. 프로필에서 기본 배경, 보유 포토 또는 보유 카드 일러스트를 고르고 레이아웃·표시 정보·색상을 저장합니다.
3. 보유 장식과 칭호를 적용하고, 보유 카드 중 버디 카드를 선택합니다. 이름·자기소개·즐겨찾는 아이돌의 기존 저장 기능도 함께 유지합니다.
4. 일러스트가 실제로 존재하고 현재 카드에서 열려 있는 경우, 카드 상세 화면에서 표시 일러스트를 바꿉니다. 저장한 선택은 서버와 앱을 다시 시작해도 유지됩니다.

| 설정 | 저장하는 값과 범위 |
| --- | --- |
| 포토 이름 | 선택한 보유 포토의 이름만 변경 |
| 포토 잠금 | 선택한 보유 포토마다 현재 잠금 상태를 전환; 새 포토 생성 없음 |
| 프로필 배경 | 기본/카드/포토 구분과 카드·포토 ID, 카드 표시 유형 |
| 프로필 레이아웃 | 기존 레이아웃·정보·색상의 세 선택값 |
| 프로필 장식·칭호 | 마스터에 존재하는 현재 계정의 보유 항목 적용 |
| 버디 카드 | 마스터에 존재하는 현재 계정의 보유 카드 지정 |
| 카드 일러스트 | 현재 카드의 표시 유형만 변경; 성장·한계돌파·진화는 변경하지 않음 |
| 이름·자기소개·즐겨찾는 아이돌 | 기존 사용자 또는 프로필 설정 저장 기능 유지 |

## 일반 계정과 전체 해금 감상 모드

일반 계정은 기존 보유 카드·포토·장식·칭호만 선택할 수 있습니다. 설정 저장 요청이 새 소유권이나 재화·성장·미션·보상을 만들지 않습니다.

명시적으로 선택한 전체 해금 감상 모드는 별도 저장소의 감상 계정에 원본 장식 **361종**을 준비합니다. 기존에 있는 장식 행과 선택한 장식, 알 수 없는 필드는 유지하고 누락된 항목만 더합니다. 이전 감상 계정도 다시 준비할 때 보완하며, 일반 계정에는 이 추가를 적용하지 않습니다. 사용자 지정 카탈로그에 장식 자료가 없고 원본 버전과도 다르면 기존 동작대로 새 장식을 준비하지 않습니다.

카드 일러스트는 원본 **CardImage 611개 조합**의 카드 ID·표시 유형과 현재 카드의 희귀도·진화 상태를 함께 확인합니다. 초기 5성 카드에는 표시 유형 1이 없고 유형 2만 있는 경우가 있으므로, 모든 카드에 같은 그림 목록을 만들어 주지 않습니다. 진화 상태가 있어도 실제 유형 3 그림이 없으면 선택할 수 없습니다.

CardImage·Decoration 보완 자료는 SHA-256으로 고정한 공개 원본의 암호화 마스터 팩에서 추출했습니다. 해당 JSON이 없고 카탈로그 버전이 정확히 일치할 때만 필요한 표 하나를 지연 로드합니다. 이미 존재하는 빈 파일·손상 파일이나 다른 버전의 카탈로그를 보완 자료로 우회하지 않습니다. [추출 자료·개수·해시와 검증 근거](preference-master-data.json).

## 저장·재시도와 데이터 보존

설정은 한 트랜잭션에서 검증하고 저장합니다. 선택한 항목 중 하나라도 잘못되었거나 미보유 상태이면 전체 요청을 거절하며, 일부 포토나 프로필만 먼저 바꾸지 않습니다. 같은 설정을 다시 저장하면 현재 전체 행을 응답하고 원본 스냅샷 바이트를 유지합니다. 다른 프로필·계정 식별자·세션·기존 성장·보상·포토 속성과 알 수 없는 protobuf 필드를 보존합니다.

포토 잠금 API는 원하는 최종 상태를 보내는 방식이 아니라 **현재 상태를 뒤집는 동작**입니다. 따라서 원래 요청 ID와 입력에 연결한 저장 응답을 계정 상태와 함께 원자적으로 보관합니다. 연결이 끊겨 동일 요청이 다시 오거나 서버를 재시작해도 잠금을 두 번 뒤집지 않습니다. 같은 요청 ID를 다른 입력에 재사용하면 상태를 바꾸지 않고 거절합니다.

기본 배경으로 돌아가면 카드·포토 배경 참조를 비울 수 있습니다. 버디 카드·장식·칭호에 빈 ID를 보내 해제하는 동작과 생일 등록·변경은 이번 복구 범위에 포함하지 않습니다. 공식 금칙어 검사, 원격 친구에게 버디를 빌려주는 기능, 전체 게임 진행 복구도 이 설정 저장에 포함되지 않습니다.

개인 Dream 카탈로그는 전체 포토 바이트와 수집 당시의 보유 상태를 대조합니다. 포토 이름이나 잠금을 바꾸면 기존 카탈로그를 최신 상태로 간주하지 않으며, 자동으로 과거 검증 지문을 다시 연결하지 않습니다.

## 계약과 입력 범위

| RPC | 요청의 주요 필드 | 갱신 응답 |
| --- | --- | --- |
| `Photo.Update` | `photoId #1`, `name #2` | 해당 전체 포토 행 |
| `Photo.SwitchLock` | 반복 `photoIds #1`; 원본 요청 ID 필요 | 선택한 전체 포토 행들 |
| `Profile.UpdateBackground` | `backgroundType #1`, `favoriteCardId #2`, `favoritePhotoId #3`, `favoriteCardDisplayType #4` | 전체 프로필 행 |
| `Profile.UpdateDecoration` | `decorationId #1` | 전체 프로필 행 |
| `Profile.UpdateBuddyCard` | `cardId #1` | 전체 사용자 행 |
| `Card.UpdateDisplayType` | `cardId #1`, `displayType #2` | 해당 전체 카드 행 |
| `Profile.UpdateLayout` | `layoutType #1`, `informationType #2`, `colorType #3` | 전체 프로필 행 |

갱신 행은 원본 계약의 `commonResponse #9999 → updatedData`로 반환합니다. 포토 잠금은 원본 래퍼가 반복 ID만 구성하고 캐시되는 요청 문맥을 사용한다는 근거를 따릅니다. 카드 상세의 확인 화면은 명시적 표시 유형 1~3을 보내므로 해당 RPC의 0(Unknown)은 거절합니다. 프로필 배경의 자동 표시 0은 현재 카드 상태에서 실제 그림 유형을 계산해 검증한 뒤 유지합니다.

포토 이름은 1~12 UTF-16 코드 단위이며 공백만 있는 이름·서로게이트 문자·결합 문자·일부 기호를 원본 입력 규칙에 맞춰 거절합니다. 직접 전달한 CR/LF/탭도 거절하고, 허용된 문자를 자르거나 정규화하지 않습니다. 프로필 레이아웃의 세 열거형은 각각 정의된 값 1~4만 저장합니다.

이전 문서의 “v0.3.4 미게시 후보” 설명은 해당 기능을 처음 추가했을 당시의 배포 기록입니다. 현재 배포판의 검증 상태와 파일은 위 실행 및 최신 릴리즈 안내를 기준으로 확인합니다. 실제 기기의 편집 화면 성공 여부는 서버 계약·저장·재시도 검사와 구분합니다.
