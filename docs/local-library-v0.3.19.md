# v0.3.19 촬영·의상·언어·리소스 보관

서버와 연결용 게임 클라이언트를 각각 업데이트한다. 기존 앱과 데이터를 삭제하지 않는다. 목록 정렬·언어·리소스 보관 위치를 바꾸면 서버를 재시작하고 게임 타이틀에서 다시 로그인한다.

## 촬영 목록과 의상

- 라이브 촬영에서 영상 MV만 숨기는 선택을 제공한다. 원본 `Music.mvAssetId`가 있고 3D 공연을 지원하지 않는 항목만 제외한다.
- MV는 최근 공개순이 기본이며 오래된 공개순·제목순·ID순을 선택할 수 있다. 실제 공개 시각으로 순서를 미리 만든다.
- 의상은 원본 획득순이 기본이며 최근/오래된 공개순·이름순·ID순을 선택할 수 있다. 사용자 획득 시각·소유·착용 기록을 바꾸지 않는다.
- 의상 사용자 정렬은 원본의 획득일 우선 비교 대신 원본의 마스터 순서 우선 함수를 사용한다. 원본 정렬 선택은 기존 함수를 유지한다.
- Android 일반 촬영도 시작 시 UI를 한 번 숨기며 이후 사용자가 켠 상태를 유지한다.

## Downloads에서 직접 제공

최신 Elichika의 `Downloads/skusta`처럼 게임 전용 최상위 폴더를 둔다.

```text
Downloads/IdolyPride/
├── octo-cache/       Android CDN 원본 파일
├── octo-cache-ios/   iOS CDN 원본 파일
└── exports/          선택적으로 내보낸 보관 ZIP
```

게임의 개별 요청, 전체 받기, 가져오기·내보내기가 같은 플랫폼별 캐시를 사용한다. 받은 원본 바이트를 크기·MD5로 확인한 뒤 완성 파일로 교체한다. 게임에도 이 파일을 바로 제공한다. 기존 앱 전용 캐시는 확인 후 복사해 재사용하며 기존 파일을 삭제하지 않는다. 계정·설정·마스터는 기존 앱 데이터 폴더에 유지한다.

Android 11 이상에서 직접 보관하려면 Elichika와 같은 파일 관리 권한을 허용해야 한다. 앱 전용 보관도 명시적으로 선택할 수 있다. Downloads를 선택했는데 권한이 없으면 접근 오류를 표시하며 다른 위치로 자동 전환하지 않는다. Mac은 Downloads 접근 권한이 필요하다.

전체 받기는 사용자가 시작한 경우에만 동작한다. 포함된 목록은 플랫폼별 54,442개이며 Android 약39.32GB, iOS 약39.23GB다. 동시 취득은 최대2개다. 다시 시작하면 크기·MD5를 확인한 완료 파일부터 재사용하고, 중단된 단일 파일의 바이트 단위 재개는 제공하지 않는다. 목록 밖의 파일이나 CDN에서 이미 사라진 파일을 생성하지 않는다.

ZIP은 추가 이동·백업을 위한 선택 기능이다. ZIP64를 스트리밍해 큰 임시 ZIP 복사본을 만들지 않는다. 완성 여부와 오류 수를 확인한 뒤 내보낸 파일을 공개하며, 일부만 보관된 ZIP에는 미보관 수를 표시한다. 가져오기는 알려진 원본 항목의 크기·MD5를 검사하고 성공한 파일을 유지한다. 계정·인증·설정 파일은 ZIP에 넣지 않는다.

## 미리 만든 언어 데이터

일본어·한국어·영어별 마스터 팩을 준비한다. 한국어는 CyleAR의 모듈이 연결한 `CyleAR/ipr-translation-data-ko`의 고정 리비전, 영어는 Project-Hoshimi의 `ipr-translation-data-en`을 사용한다. 매 프레임 문자열을 덮어쓰는 번역 훅은 추가하지 않는다.

한국어·영어 각각90개 소스 테이블 중89개 테이블을 적용했다. 원본 배열 전체를 대상으로 한 튜토리얼 규칙은 해석을 추정하지 않고 일본어로 유지한다. 번역 누락 행·필드는 일본어를 유지한다. 번역은 마스터의 표시 텍스트 범위이며, ADV 대사·고정 UI·이미지 번역의 완료를 뜻하지 않는다. 정확한 소스·권리 표시·범위는 [번역 데이터 안내](translation-catalog.md)를 따른다.

공개 날짜·ID·자산 참조·조건·소유 정보는 보존한다. 언어와 목록 정렬 팩은 오프라인에서 만든 뒤 시작 시 작은 마스터 태그만 조합한다. 번역 변경 후 타이틀 재로그인이 필요하며, 첫 로딩에서 선택한 언어 팩을 게임 캐시에 받는다.

## 검증 범위

원본 Android·iOS의 목록 비교·필드·함수 ABI, 언어별 SQLCipher/protobuf 팩 왕복, 파일 검증·취소·동시 요청·오프라인 가져오기와 설정 저장을 검사한다. Android 의상룸 수정은 확인된 표시 실패 후의 종료 대기 경로로 한정하고, 실제 폰에서 발생한 프리징 원인을 확정한 것으로 취급하지 않는다. 의상룸 고정 단계·해제 횟수는 계정 정보 없이 진단에 남긴다. 실제 폰·Mac 화면의 최종 동작과 성능 측정은 별도다.
