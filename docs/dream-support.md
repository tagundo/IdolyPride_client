# 이미지 트레이닝: 보존 자료와 읽기 전용 진입

현재 소스는 `Home.Enter.eventInfo.dreamInfo`와 `Dream.Top`의 읽기 경로를 준비합니다. 공개 Home 응답에서 관측된 기간은 **2026-10-15 12:00~2026-11-15 11:59:59 JST**입니다. 이 자료는 해당 월의 관측 기간이며 전체 이미지 트레이닝 기능이나 생성한 에리어가 그때 삭제된다는 근거로 사용하지 않습니다. 기간 종료 뒤 새로운 시즌·월간 미션·매뉴얼을 자동으로 생성하거나 기기의 시각을 바꾸지 않습니다.

런타임 카탈로그 위치는 기본적으로 `master-json`의 상위 디렉터리의 `dream-catalog.json`입니다. `Dream(..., catalog_path=...)`로 명시할 수도 있습니다. 파일이 없는 이전 payload에서는 새 처리기를 사용하지 않아 기존 홈 동작을 유지합니다. 공개 카탈로그의 스키마·마스터 버전·원본 SHA-256·Dream 설정·매뉴얼·기간 조건과 메인 16지역의 참조를 검증합니다. 해당 지역을 완료하지 않은 계정의 홈 표시는 잠금 상태이며 `Dream.Top`은 거절합니다.

표시 대상은 해당 로컬 계정이 실제 보유한 4성 이상 포토입니다. 이름이나 다른 계정의 식별자·능력치를 가져오지 않습니다. 이번 읽기 전용 범위에서는 포토의 `isDisableGenerateArea`를 true로 보내며, 이는 로컬 생성 기능 미지원 표시입니다. 공식 서버의 포토별 생성 자격 판정을 재현했다는 뜻은 아닙니다. 새 포토·생성 에리어·클리어·성장·미션 진행·로그인 보상·매뉴얼을 지급하지 않습니다.

`User.Get`의 포토는 `isDreamBase`와 재료 포토 메타데이터만 가지고 있습니다. 생성된 퀘스트·성장 계획·진행 정보는 별도 `Dream.Top`·`Dream.ListQuest` 응답이 필요합니다. 이미 `isDreamBase`인 포토에 해당 정보가 없으면 빈 에리어나 새 진행도로 바꾸지 않고 오류를 반환합니다. `GenerateArea`·`StartQuest`·`SkipQuest`·`ResetArea`와 포토 강화는 구현 범위 밖입니다.

새 포토를 직접 찍는 경로도 별도로 복원해야 합니다. 원본 촬영창은 `Photo.ListShooting`으로 장소·곡·표정의 계정별 잠금을 받고, 촬영 확인 뒤 원본·썸네일 이미지를 Firebase에 올린 다음 `Photo.CreateShootings`를 호출합니다. 현재 production runtime에는 보존한 촬영 잠금과 이미지 공급자를 연결하는 경로가 없습니다. 또한 원본의 직접 촬영 사진(`PhotoImageType.User=2`)과 생성 사진(`Generated=3`)의 이미지 취득 경로가 다르므로, 현재 `GetImageURL`의 로컬 정책 검사만으로 원본 갤러리나 촬영 복구를 검증했다고 표현하지 않습니다. 포토 예약 ID나 공개 장소 마스터만으로 실제 이미지·보유 포토를 만들지 않습니다.

본인 계정에서 수집한 자료가 있으면 `master-json` 상위의 `dream-private-catalog.json`을 우선 사용합니다. `Dream(..., capture_catalog_path=...)`로 경로를 지정할 수도 있습니다. `dream_capture.build_dream_catalog(schema, capture_directory, output_path=None)`는 보존 도구의 아카이브를 검사해 이 비공개 카탈로그를 만듭니다. 출력 경로를 주면 0600 권한으로 원자적으로 저장합니다. 공식 서버 호출이나 로컬 계정 변경은 하지 않습니다. 이 파일에는 개인 계정·포토 데이터가 있으므로 저장소·배포 payload에 포함하면 안 됩니다.

비공개 읽기 경로는 실제 `Master.Get`, 최초·최종 `User.Get`, `Home.Enter(skipUpdate=true)`, `Dream.Top`과 생성된 포토별 `Dream.ListQuest`를 검증합니다. 실제로 수집된 포토별 `Dream.ListMaterialPhoto`도 조회할 수 있습니다. 최종 스냅샷이 명시된 아카이브만 받고 최초·최종 계정 식별자, 스키마·마스터 버전, 원본 파일 크기·SHA-256, 요청의 `basePhotoId`, 보유 포토 참조·진행도·마스터 참조를 대조합니다. 파일 경로 조작·심볼릭 링크·중복 요청을 거절합니다. 다른 이벤트의 자료가 빠져 아카이브가 부분 완료여도 Dream의 필수 자료가 모두 있으면 변환할 수 있습니다.

재생하는 정보는 해당 아카이브의 마지막 관측 상태입니다. 현재 로컬 계정의 전체 보유 포토와 즐겨찾기 포토가 당시 상태와 일치해야 하며 잠금·강화·새 포토·삭제 등의 변경이 있으면 오래된 목록을 사용하지 않습니다. 시즌의 원래 날짜·생성 에리어·클리어 수·능력치와 수집된 재료 미리보기는 보존하지만, 응답의 계정 업데이트·삭제·로그인 보상·상점·미션 진행·알 수 없는 필드를 제거합니다. 생성과 퀘스트 플레이·스킵 플래그는 읽기 전용 상태로 보냅니다. 없는 재료 목록이나 생성 에리어는 근사 공식으로 채우지 않습니다. 수집 이후 공식 서버에서 바뀐 에리어 진행을 자동으로 감지하는 기능은 아닙니다.

카탈로그는 [공개 저장소의 고정 커밋](https://github.com/Project-Hoshimi/sumire-sr-data/tree/c40ea107b9cc8e53ae1705f82a5c39cc9fe3be02)의 Home 응답 `00033`에서 `eventInfo.dreamInfo`만 투영한 것입니다. 원본 응답의 SHA-256은 `d956979f9d04a6a69ffc640ba6c2650f5bc7f34ece0236b466b37bdfcee5a193`입니다. 공개 자료의 치환된 이름 `Player`, 계정별 해금·수령 가능 표시를 복사하지 않습니다. 표시명은 같은 버전의 `Setting.dreamAreaName`을 사용합니다. 실제 Dream.Top에만 있는 시즌 ID·랭크 색상·공지·동적 생성 공식은 이 자료에 없으므로 다른 서버의 근사 규칙으로 채우지 않습니다.

서버 API·무변경 검사는 실제 게임 화면의 이미지 트레이닝 플레이 완료 검사와 구분합니다. 이 문서는 새 앱 배포나 전체 이미지 트레이닝 플레이 지원을 뜻하지 않습니다.
