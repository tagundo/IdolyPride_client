# 홈 촬영·이벤트 캐시 수정 v0.3.24

다운로드 작업이 진행 중이면 작업을 취소하고 서버를 중지한 뒤 서버 앱만 업데이트한다. 검증이 끝난 리소스 파일은 다시 사용한다. Android 게임 v0.3.21과 PlayCover IPA v0.3.19, 공통 서버 데이터 v0.3.23은 그대로 사용한다. 서버를 다시 시작하고 게임을 완전히 종료했다가 새로 로그인한다.

## 포즈 촬영과 이벤트 메뉴

감상 모드 v0.3.23의 촬영 목록과 포즈 보유 정보가 있어도, 원본 게임은 포즈 화면을 열기 전에 홈 진입 응답의 `photoExpressions` 캐시로 촬영 가능한 캐릭터를 판정한다. 이 목록이 비어 있어 모든 캐릭터가 `撮影NG`로 표시됐다. 홈 진입 응답에 검증된 촬영 목록과 같은 업무·음악·스테이지·포즈 장면 목록을 제공한다. 기존 영상 MV 숨김 설정도 동일하게 적용한다. 원본에 모션이 없는 협업 캐릭터 등 원본 제외 조건은 유지한다.

이벤트 메뉴도 홈 진입 응답의 `eventStoryInfos`로 초기 캐시를 만든다. 별도 `Story.ListEvent` 응답만 제공한 v0.3.23에서는 홈 캐시가 비어 이벤트 메뉴의 기본 잠금 이미지가 표시됐다. 홈 응답에 동일한 이벤트 59개·291편의 현재 읽음 정보를 함께 제공한다. 표시 조건을 추가로 우회하거나 일반 계정의 진행을 변경하지 않는다.

두 변경은 감상 모드의 홈 응답을 보완한다. 일반 계정의 원본·보존 응답과 계정 재화는 유지한다. 사진 이미지 생성·업로드 기능은 이번 수정에 포함하지 않는다.

## Android 다운로드 호출 비용과 진행 정보

TLS 입력 스트림은 64KiB를 요청해도 작은 조각을 반환할 수 있다. 기존 구현은 조각마다 Java↔Python 호출, 메모리 복사, 파일 쓰기와 검사 콜백을 반복했다. 이제 기존 64KiB 버퍼 안에서 Java가 조각을 모아 전달한다. 완료된 읽기에 50ms가 지나면 Python으로 돌아가 시간 제한과 진행·취소 검사를 계속한다. 파일 전체를 메모리에 쌓지 않는다.

16KiB 조각으로 1MiB 파일 8개를 읽는 호스트 모형에서 경계 호출은 520회에서 136회로 줄었다. 실제 네트워크 읽기 횟수는 같으며 이 숫자를 실기기 다운로드 속도 향상 배수로 해석하지 않는다. 정상 완료 시 Android 연결은 기존 구현에서도 재사용될 수 있어 연결 종료 정책은 바꾸지 않았다.

Android와 Mac 서버 화면에는 다음 정보를 표시한다.

- 새로 수신한 바이트와 작업 전체 경과 시간을 기준으로 계산한 평균 수신 속도
- 검증 완료 용량과 전체 용량, 재사용한 기존 파일 수
- 현재 연결·수신·검증·저장·복사 중인 파일 수

평균 수신 속도는 기존 파일 검사와 저장에 걸린 시간도 포함한다. 회선의 최대 속도나 순간 속도를 뜻하지 않는다. 내부 진단의 단계별 누적 시간은 병렬 작업의 시간을 합한 값이므로 전체 경과 시간과 다를 수 있다. 파일 수만으로 남은 다운로드 용량을 추정하지 않는다.

기본 동시 다운로드 4개와 선택값 1·2·4·8개, 디스크 여유 공간 예약, 취소 후 쓰기 차단, 수신 중 해시와 저장 후 전체 파일 해시 검사를 유지한다.

## 검증 범위

원본 Android 6.1.1의 홈 응답→사용자 데이터 캐시→포즈 선택/이벤트 메뉴 경로를 대조했다. 회귀 검사는 홈 캐시가 비었을 때 이전 문제가 발생하는 조건, 홈 응답과 별도 목록의 일치, 읽음 정보·미지 필드·일반 계정 보존을 검사한다. 다운로드 검사는 작은 조각·EOF·초과 바이트·취소·시간 제한·해시·단계 관측을 검사한다.

배포별 전체 호스트 검사 결과와 실제 APK·Mac 앱의 코드·서명·데이터·원격 다운로드 검증은 릴리즈의 `RELEASE-VERIFICATION.json`에 기록한다. 실제 Android·Mac 기기에서의 메뉴 진입, 다운로드 속도 개선량과 Mac GUI 실행은 이번 검증과 구분한다.
