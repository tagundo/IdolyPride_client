# Android 360 LIVE 화면·UI 수정 v0.3.18

v0.3.18은 서버 v0.3.17과 함께 사용하는 Android 그래픽 진단 클라이언트 수정판이다. 서버 APK를 다시 설치하거나 게임 데이터를 지울 필요가 없다. 멀티스레드 시작 실험의 기본값과 그래픽·회전 설정은 유지한다.

[클라이언트 APK 파일 페이지](https://github.com/tagundo/IdolyPride_client/blob/downloads/android-360-v0.3.18/IdolyPride-Local-Graphics-Diagnostic-Android-arm64.apk)에서 받는다. 기존 **아이프라 진단**에 업데이트한 뒤 서버의 **진단 게임 실행**으로 연다.

## 16:9 바깥 영역 깜빡임

Android 경로는 공연 카메라의 물리 렌즈·센서 설정이 바뀌거나 안전한 투영 검사가 실패할 때 원래 16:9 렌더 타깃을 복원하고 다음 프레임에 다시 확장할 수 있었다. 이 반복은 빈 타깃 표시와 재할당을 일으킬 수 있다. 사용자 기록에는 해당 분기의 호출 횟수가 없어, 실제 기기의 깜빡임 원인을 이 경로 하나로 확정하지는 않는다.

Android에서도 기존 렌더 타깃을 유지한 채 원래 카메라의 투영을 다시 읽는다. 검사가 실패하면 한 번 원복하고 같은 설정·표시 영역에서 반복하지 않는다. 설정·실제 표시 영역·카메라·촬영 세션이 바뀌면 다시 검사한다. 확장에 성공하지 못한 상태를 적용 완료로 표시하지 않는다. 카메라의 자동 종횡비와 원래 렌즈는 원복 시 복구한다.

## 화면 가장자리의 360 조작 버튼

UI 표시 버튼은 왼쪽 위, 종료 버튼은 왼쪽 아래, 카메라 버튼·말풍선·선택 패널은 오른쪽 아래의 실제 촬영 표시 영역을 따른다. 기존 버튼의 여백과 크기를 유지하며 팝업도 함께 이동한다. 원래 Android 6.1.1의 타입·필드·함수 접두부를 확인한 계약만 사용한다. 화면 확장을 끄거나 360 LIVE에서 나가면 원래 배치로 복원한다.

UI는 촬영 시작 때 한 번 숨긴다. 사용자가 다시 켠 뒤에는 그 선택을 유지한다. 버튼을 숨기는 것만으로 게임 원래 UI의 모든 갱신이 중지되는 것은 아니다.

## 연산 범위와 검증 한계

설정 통신은 별도 작업 스레드에서 약 2초마다 실행한다. UI 배치 보정은 Unity 콜백에서 수행하므로 비용이 없지는 않다. 같은 호출 안의 공통 좌표 변환을 재사용한다. 정상 3부모 구성에서는 좌표 변환이 14회에서 11회로 줄고, 모든 대상의 부모가 같으면 8회, 기존 표시 영역과 정확히 같으면 0회다. 위치 읽기 15회는 유지하고 위치가 같으면 쓰지 않는다. 프레임을 넘겨 게임 객체의 원시 포인터나 좌표를 캐시하지 않아 해상도 변경·부모 변경·게임 자체의 재배치를 계속 감지한다.

호스트 검사는 재할당 반복 방지, 투영 원복, 화면비별 버튼 위치와 게임 자체 UI 변경·세션 종료를 검증한다. 이는 실제 Android 화면의 깜빡임 소멸이나 FPS 향상을 측정한 결과와 구분한다. 첨부된 MT 기록의 해석과 비교 방법은 [MT 확인 안내](android-mt-verification.md)를 참고한다.
