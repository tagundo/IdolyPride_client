# Integrated iOS server contract

Device iPhone/iPad is primary; PlayCover may convert the same device IPA. No Mac executable, subprocess launcher, or desktop Python runtime is embedded.

- Native framework: `Frameworks/IdolyEmbeddedServer.framework/IdolyEmbeddedServer`; real iOS arm64 with matching Python 3.13 framework and iOS native stdlib frameworks. The original presentation framework remains intact.
- Native built-in CPython module `_idoly_ios`: `aes_cbc(encrypt, key, iv, data) -> bytes`; `open_url(url, timeout=...) -> response` supporting `read(n)`, `close()`, `getcode()`, `.headers`, context manager. Native HTTPS uses OS trust and a bounded streaming queue, not full-file NSData. `post_event(json_string)` delivers a bounded event to the native startup/settings controller.
- Python module `idoly_local.ios_host`: `start(bundle_dir, data_dir, resource_dir) -> dict` on a dedicated worker (blocking until installed and both listeners ready); `command(raw_json) -> str` on native serial worker; `foreground() -> dict`; `close()`. Native sets pure-Python protobuf before any import. No process signals/stdin/fork; no interpreter finalization while game or Python threads are alive.
- `bundle_dir` is `<app>/LocalServer`: `ServerData.zip`, `bundledTranslations.zip`, generated `bundledTranslations.json`, `python/` package sources and pure dependencies. Interpreter search path also contains `<app>/python-stdlib` and its `lib-dynload`. All loadable native modules are signed frameworks with valid `.fwork` mappings, not unconverted `.so` files.
- Private state: `Library/Application Support/IdolyPrideLocal`; retained resources: `Documents/IdolyPride`. Bundled data is read-only. Existing files/DBs are preserved. Default language `ko` for this Korean client and fresh default media/all-unlock mode true, with a separate normal profile preserved.
- Settings bridge is local bundled WKWebView JS `window.webkit.messageHandlers.idolyServer.postMessage({id, action, ...})`. Only main-frame trusted local settings content is accepted; native replies with `window.idolyServerReply(id, result)` and emits `window.idolyServerEvent(event)`. No unauthenticated localhost admin HTTP endpoints.
- Core actions: `status`, `save_options` (media_mode/download_missing_resources/language), `save_presentation` (settings object), `save_playback` (settings object), `save_media` (settings object), `resources_preview`, `resources_download` (parallelism), `resources_cancel` (job_id), `resources_import` (native-approved copied ZIP path), `resources_export`. Runtime-affecting profile/language changes are saved for next launch; no surprise mid-game server restart. Exports go to app-owned temp/exports then native Files picker; imports are copied into app-owned imports before Python reads them.
- Startup must not run heavy Python/payload work under dyld constructors or block the main thread. Install presentation gateways first. Intercept the exact audited public UnityFramework run-main entry before its warmup, start UIKit once with the native host delegate, and prepare the independent server launcher on a background worker. Readiness enables Game Start but never forwards Unity automatically. After the user presses the real launch button, apply pending game options, verify the selected resource-only language bundle outside the signed app, and select it through the public Unity data-bundle API. Verify the original lazy bundle-root getter only after selection, then invoke the original cold runEmbedded path exactly once. Recheck the consumed root before original warmup and after initialization; never reset Unity caches or reinitialize its runtime. Preserve the original late-init budget-setting order and retire the placeholder window when handing off to the actual game window. Refuse an unsupported entry path visibly instead of falling back to a late-only capture.
- During gameplay, a single finger held for two seconds in the upper-right 64-point safe-area corner reopens the server menu. Normal short touches/drags pass through; no three-finger gesture. On Mac, a runtime-detected AppKit app-menu item and Command+Shift+, are secondary entries into the same controller without linking AppKit into the iOS framework. Menu/gesture installation is event-driven and idempotent across window/menu changes; no continuously visible overlay or frame polling. Launcher/settings WKWebViews are released on game entry/close. Background callbacks must not synchronously join threads; game and server suspend together. Foreground checks/recovery run asynchronously.

Artifacts remain unsigned/ad-hoc development IPAs until user sideload/PlayCover signing. Host package checks and simulator core tests do not establish actual phone gameplay, FPS, or PlayCover compatibility.

## Prebuilt client languages

One IPA retains the pinned Korean base and carries a verified incremental ZIP for Japanese/English resources.assets and global-metadata.dat. Common Data files and the shared audited font are copied to an owned cache; only links between owned cache files are used. No signed bundle file is rewritten. The selected complete resource-only bundle is immutable for that game session. Before game entry, server options and language Data must match; after entry language changes require app restart. Available translations are reused, and missing text/image translations retain their source content.

NSBundle resolution is specialized only for the fixed local.idoly.client-data identifier. All other identifiers keep their original Foundation lookup. Metadata and path checks run on main immediately before selection; asset verification/copy and Python control run on the worker. An absent or mismatched initialization API never enables Game Start. Native server controls remain available without the web bridge. Early status/error responses preserve request IDs, and closing a menu releases its WebView without stopping the process-owned server.

- Server interface language changes persist separately and update the native launcher, status, buttons, failure alerts, Mac menu, and WebView immediately. In-flight status/full-save responses must not roll back a newer interface selection or mutate pending game options. Game language remains fixed for one process; changing it after launch applies on the next complete app launch.
