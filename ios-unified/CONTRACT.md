# Integrated iOS server contract

Device iPhone/iPad is primary; PlayCover may convert the same device IPA. No Mac executable, subprocess launcher, or desktop Python runtime is embedded.

- Native framework: `Frameworks/IdolyEmbeddedServer.framework/IdolyEmbeddedServer`; real iOS arm64 with matching Python 3.13 framework and iOS native stdlib frameworks. The original presentation framework remains intact.
- Native built-in CPython module `_idoly_ios`: `aes_cbc(encrypt, key, iv, data) -> bytes`; `open_url(url, timeout=...) -> response` supporting `read(n)`, `close()`, `getcode()`, `.headers`, context manager. Native HTTPS uses OS trust and a bounded streaming queue, not full-file NSData. `post_event(json_string)` delivers a bounded event to the native startup/settings controller.
- Python module `idoly_local.ios_host`: `start(bundle_dir, data_dir, resource_dir) -> dict` on a dedicated worker (blocking until installed and both listeners ready); `command(raw_json) -> str` on native serial worker; `foreground() -> dict`; `close()`. Native sets pure-Python protobuf before any import. No process signals/stdin/fork; no interpreter finalization while game or Python threads are alive.
- `bundle_dir` is `<app>/LocalServer`: `ServerData.zip`, `bundledTranslations.zip`, generated `bundledTranslations.json`, `python/` package sources and pure dependencies. Interpreter search path also contains `<app>/python-stdlib` and its `lib-dynload`. All loadable native modules are signed frameworks with valid `.fwork` mappings, not unconverted `.so` files.
- Private state: `Library/Application Support/IdolyPrideLocal`; retained resources: `Documents/IdolyPride`. Bundled data is read-only. Existing files/DBs are preserved. Default language `ko` for this Korean client and fresh default media/all-unlock mode true, with a separate normal profile preserved.
- Settings bridge is local bundled WKWebView JS `window.webkit.messageHandlers.idolyServer.postMessage({id, action, ...})`. Only main-frame trusted local settings content is accepted; native replies with `window.idolyServerReply(id, result)` and emits `window.idolyServerEvent(event)`. No unauthenticated localhost admin HTTP endpoints.
- Core actions: `status`, `save_options` (media_mode/download_missing_resources/language), `save_presentation` (settings object), `save_playback` (settings object), `save_media` (settings object), `resources_preview`, `resources_download` (parallelism), `resources_cancel` (job_id), `resources_import` (native-approved copied ZIP path), `resources_export`. Runtime-affecting profile/language changes are saved for next launch; no surprise mid-game server restart. Exports go to app-owned temp/exports then native Files picker; imports are copied into app-owned imports before Python reads them.
- Startup must not run heavy Python/file work under dyld constructors or block the main thread. Install presentation gateways first. Hook exact UnityAppController `startUnity:` signature to defer original invocation while a background server worker prepares data. Resume original main-thread invocation exactly once after readiness. Fail visibly/retry instead of letting initial login race the server.
- Server settings can be opened by a three-finger long press; no continuously visible overlay or polling when settings is closed. Settings UI is released when closed. Background callbacks must not synchronously join threads; game and server suspend together. Foreground checks/recovery run asynchronously.

Artifacts remain unsigned/ad-hoc development IPAs until user sideload/PlayCover signing. Host package checks and simulator core tests do not establish actual phone gameplay, FPS, or PlayCover compatibility.
