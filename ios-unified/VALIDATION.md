## PlayCover 파일 다운로드 오류 수정

사용자 오류 실행의 전체 추적에서 `assets._serve → mimetypes.guess_type → init → read`가 `/etc/apache2/mime.types`를 열다가 `PermissionError`를 내는 것을 확인했습니다. TCP와 로그인·마스터 목록 응답은 성공했지만, 파일 응답 헤더를 보내기 전에 핸들러가 종료돼 게임에는 `Cannot connect to destination host`로 보였습니다. 전송 시작 전 예외여서 기존 마스터 전송·Octo 카운터가 모두 0이었습니다.

정적 파일은 내장된 형식 표의 불변 사본을 사용합니다. DB·pack·알 수 없는 확장자는 `application/octet-stream`으로 제공하고 이미지·JSON 형식은 보존합니다. 요청 처리에서 시스템 MIME 파일을 읽거나 전역 MIME 데이터베이스를 초기화하지 않습니다. 존재하지만 읽기가 거부되는 MIME 파일 조건을 재현하고, 실제 HTTP GET·HEAD·Range 및 이미지·JSON 응답이 정상임을 확인했습니다.

상단 서버 상태·버튼·안내문은 창 크기에 맞춰 확대합니다. 진단에는 표시된 내용을 복사하는 네이티브 버튼을 추가했고, UTF-8 32KiB를 넘는 내용은 생략 표시를 포함합니다. HEAD·404를 포함하는 HTTP 요청 기록과 최근 실패 경로를 유지하며, 게임 시작 전에 앱 작업 스레드에서 고정된 로컬 HTTP 주소에 실제 요청을 보냅니다.

## 보고된 Mac 충돌과 수정

156.9103과 156.9104의 Mac 보고서는 같은 Unity 반환 위치 0x15f20에서 종료됐습니다. 원본의 Keyboard.mm 260행 검사 `[KeyboardDelegate Initialize] called after creating keyboard`입니다. 공개 getter만 차단한 이전 수정은 이미 존재하는 키보드 상태를 처리하지 못했습니다.

고정된 원본에서 Initialize의 미생성 경로와 Instance의 미생성 경로가 같은 클래스에 `_objc_alloc_init`을 호출하고 같은 전역값에 저장함을 확인했습니다. Initialize의 기생성 경로에는 추가 설정 없이 assertion과 반환만 있습니다. 수정판은 같은 클래스의 살아 있는 객체가 이미 있으면 재사용하고, 없거나 지원하지 않는 상태면 원본 구현과 예외를 유지합니다. 공개 getter를 변경하지 않고 객체·입력란을 교체하거나 Destroy로 초기화하지 않습니다.

기기용 경로는 원본 UUID·RVA·ABI와 Initialize 184바이트, Instance 80바이트, Destroy 16바이트의 전체 본문을 확인합니다. 읽기 전용으로 접근하는 전역값은 정렬된 __DATA,__bss 내부 주소인지 검증합니다. 보호 설치는 게임 시작 직전이며 실패하면 게임을 넘기지 않고 서버 메뉴에서 오류를 표시합니다. 실제 외부 조회 호출자는 보고서만으로 특정하지 않았습니다. Foundation fixture와 Simulator의 대역 Unity 검사는 실제 PlayCover 전체 실행을 대신하지 않습니다.

## 번역 범위와 남은 검증

한 IPA의 언어 선택은 번역 자료의 완성률과 별개입니다. 번역이 없는 문구와 번역 이미지가 없는 항목은 원본을 유지합니다. 영어 UI 입력 검사에는 누락 키 17개가 기록돼 있으며 완전 번역본을 뜻하지 않습니다.

iPhone·iPad 실기기의 실제 게임·MV·성능과 새 IPA의 PlayCover 실행은 아직 검증하지 않았습니다. 모서리 제스처는 구성과 영역 계산을 검증했으며 실제 손가락·마우스 입력은 별도 확인 대상입니다. Simulator의 가짜 Unity 진입점 결과는 서버 코어와 시작 흐름 검사입니다. 기기용 IPA에는 검사용 가짜 Unity 코드와 우회를 넣지 않으며 개인 서명이 필요합니다. 선택적인 실험용 Go 라이브 시뮬레이터는 이 iOS 이식에 포함하지 않았습니다.
