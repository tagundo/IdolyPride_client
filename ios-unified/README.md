# iPhone·iPad 통합 IPA

빌드 `156.9114` 통합 IPA 시험판입니다. 로컬 서버와 일본어·한국어·영어 클라이언트 데이터를 하나의 `IdolyPride-6.1.1-Unified-iOS.ipa`에 넣습니다. iPhone·iPad를 우선하며, 기기 설치에는 개인 서명이 필요합니다.

[검증된 통합 IPA 다운로드](https://github.com/tagundo/IdolyPride_client/raw/48ddc99687c608a1f7a0b2e586619a3f7927f57b/IdolyPride-6.1.1-Unified-iOS.ipa)와 [검증 범위](VALIDATION.md)를 확인할 수 있습니다. 실제 macOS Foundation·AppKit, 세 언어의 Data 재구성·캐시 재사용, 새 iOS Simulator의 서버 선행 시작·게임 시작 버튼·설정 화면·메뉴 종료 후 서버 유지 검사를 통과했습니다.

156.9114는 공통 서버의 프로필·포토 편집 묶음을 포함합니다. 버디 카드·장식·배경·카드 이미지 선택과 보유 포토 잠금 전환을 복구하고, 기존 감상 계정의 장식 361종을 보완합니다. 미션·일일/콘테스트/타워는 실제 저장된 목록과 기록을 읽는 범위입니다. [v0.3.34 변경·검증 기록](../docs/releases/recovery-v0.3.34.md)을 참고하세요. 128×128 포인트의 2초 메뉴 제스처, 언어 전환·SIGPIPE 수정과 기존 최적화도 유지합니다.

156.9113은 게임 중 서버 메뉴를 여는 오른쪽 위 영역을 64×64에서 **128×128 포인트**로 넓혔습니다. 작은 안전 영역은 화면 안으로 제한하며 **2초·한 손가락·이동 제한과 일반 터치 전달**은 유지합니다. 공통 서버에는 보유 칭호 적용 복구와 예외의 게임 호출 위치 표시를 포함합니다. [v0.3.33 변경·검증 기록](../docs/releases/recovery-v0.3.33.md)을 참고하세요. Enumerable.Where 개별 오류의 원인은 아직 확인되지 않았습니다.

156.9112는 세 플랫폼 공통 서버 최적화를 포함합니다. 전체 진단 기록을 복사한 뒤 버리던 상태 조회를 요약 전용으로 바꾸고, 다음 언어 검증 전에 이전 검사 객체를 해제하며, 동일한 리소스 지문을 임시 결합 버퍼 없이 계산합니다. 번역 범위·캐시 리비전·내보낸 기록은 이전과 같습니다. [v0.3.32 측정·검증 기록](../docs/releases/optimization-v0.3.32.md)과 [성공한 Actions 실행](https://github.com/tagundo/IdolyPride_client/actions/runs/43710465014)을 참고하세요. 기존 SIGPIPE·언어 선택 수정과 다섯 번의 재실행 검사를 유지했습니다. 실제 게임 FPS와 기기 전체 시작 시간 개선을 뜻하지 않습니다.

156.9111은 언어를 저장하고 다시 연 뒤 게임 시작 전 서버 메뉴에서 앱이 종료되던 SIGPIPE 오류를 수정합니다. 원본 Unity가 준비 단계에서 적용하던 신호 처리를 서버 시작 전에 먼저 적용하고, 현재 처리 상태를 다시 확인합니다. 실제 Mac의 새 프로세스에서 기본 신호 상태를 강제로 복원한 뒤 끊긴 소켓 쓰기가 EPIPE로 끝나고 프로세스가 살아 있는지 검사했습니다. 같은 Simulator 저장소에서 한국어→영어→일본어→영어→한국어로 다섯 번 종료·재실행하고, 돌아온 영어·한국어 파일의 동일성과 전체 해시를 확인했습니다. 자동화 검사와 게시 IPA 전체 SHA-256 검증을 통과했으며, 이 수정판의 실제 PlayCover·iPhone·iPad 재확인은 별도 대상입니다. 기존 계정·다운로드를 삭제하지 않고 업데이트한 뒤 앱을 완전히 종료·재실행하세요.

156.9110은 게임 언어를 바꾸고 재실행해도 내장 UI가 한국어로 남던 시작 순서를 수정했습니다. Unity 준비 전에 서버 메뉴를 열고, 선택한 언어 데이터를 검증한 다음 원본의 내장 실행 경로를 한 번 시작합니다. 서버 화면 언어는 상단 제목·상태·버튼과 Mac 메뉴까지 즉시 저장·반영합니다. 사용자는 실제 PlayCover에서 일본어→영어 전환이 정상이라고 확인했으며, 이어 한국어로 바꾸고 재실행했을 때 발생한 게임 시작 전 SIGPIPE 종료는 156.9111에서 처리합니다.

156.9109는 서버가 최초 리소스를 받아 검증하는 동안 게임의 10초 수신 대기 제한에 걸려 E209가 발생하는 경우를 수정합니다. 통합 앱의 로컬 연결을 확인하고 원본 SDK의 해당 설정을 서버 처리 한도에 맞춘 330초로 적용한 뒤 읽어서 확인합니다. 이미 검증된 파일과 계정은 유지합니다. 시뮬레이터에서 준비·초기화·첫 대기 작업의 순서와 적용값을 검사했습니다. 사용자가 156.9109를 Mac의 PlayCover에서 재시험하여 홈 화면과 새 화면 모두 정상이라고 확인했습니다.

156.9108은 마스터 다운로드 이후 빈 에셋 파일명으로 요청해 E206이 발생하던 오류를 수정합니다. 번역 리소스의 내부 캐시 식별자는 유지하고, 게임의 Octo SDK에 전달하는 파일명만 원본과 같은 6글자 형식으로 제공합니다. 목록 리비전을 한 번 올려 기존 클라이언트의 잘못된 메타데이터를 갱신하며, 이미 받은 리소스·계정은 재사용합니다. 실제 iOS 런타임에서 암호화된 목록의 54,442개 항목과 번역 이미지의 전체 전송·MD5·길이·ETag를 검사합니다.

156.9107은 PlayCover에서 파일 다운로드가 끊기던 서버 오류를 수정합니다. 파일 형식을 판별하는 Python 코드가 `/etc/apache2/mime.types`를 읽다가 샌드박스의 `PermissionError`를 내고 응답 헤더 전송 전에 종료됐습니다. 정적 파일은 내장된 형식 표로 처리하며 시스템 MIME 파일에 접근하지 않습니다. 같은 권한 거부 조건과 실제 마스터 파일의 HEAD·부분 전송을 검사합니다.

상단 서버 상태와 버튼도 창 크기에 맞춰 확대하고, 진단에 **진단 전체 복사** 버튼을 추가했습니다. 게임 시작 전에는 앱 내부에서 로컬 HTTP 연결을 확인하고, 진단에 HEAD·404를 포함한 요청 기록과 최근 실패 경로를 보관합니다. 기존 키보드 재사용·언어 선택·메뉴를 닫은 뒤 서버 유지 동작을 함께 검사합니다.

## 실행과 설정

앱을 열면 서버 메뉴를 먼저 표시하고, Unity의 초기화 호출과 독립적으로 서버와 리소스 서버를 준비합니다. **서버 시작** 버튼으로 시작할 수 있고, 실패하면 상태·오류를 확인하고 **다시 시도**할 수 있습니다. 서버 준비가 끝난 뒤 **게임 시작**을 눌러야 게임에 진입합니다.

게임 중에는 화면 오른쪽 위 안전 영역의 128×128 포인트를 한 손가락으로 **2초간 길게 눌러** 서버 메뉴를 다시 엽니다. 짧은 터치와 드래그는 일반 게임 입력으로 전달합니다. Mac에서는 앱 메뉴의 **로컬 서버 설정…** 또는 **⌘⇧,**도 사용할 수 있습니다. 메뉴의 **게임으로 돌아가기**는 설정 화면만 닫고 서버를 유지합니다. 통합 앱 자체를 종료하면 게임과 서버가 함께 종료됩니다.

설정 화면은 가로 창과 큰 게임 해상도에 맞춰 영역·글자·컨트롤 크기를 조정합니다. 그래픽 품질은 기존 서버 앱과 같은 이름과 숫자 값 `0 / 10 / 20 / 30 / 40 / 100`을 표시합니다. 렌더 배율은 **최대 2배**, 렌더 버퍼는 **최대 4096px**까지 프리셋으로 선택하고, 지원 범위 내의 직접 입력값도 보존합니다. 직접 입력 지원 범위는 배율 `0.25–2`, 버퍼 `256–4096px`입니다.

**서버 화면 언어**와 **게임 언어**는 별개입니다. 서버 화면은 기기 언어를 기본으로 일본어·한국어·영어를 지원합니다. 서버 화면 언어 선택은 다른 미저장 게임 설정을 바꾸지 않고 즉시 저장되며, 네이티브 상단과 Mac 메뉴에도 적용됩니다. 게임 시작 전에 게임 언어를 선택하고 저장하면 **게임 시작** 때 해당 언어 데이터를 준비합니다. 게임에 진입한 뒤 바꾼 게임 언어는 다음 앱 실행부터 적용됩니다. 번역이 없는 문구와 번역 이미지가 없는 항목은 원본으로 표시합니다.

해금 모드·그래픽·화면 확장·촬영 옵션, 리소스 다운로드와 ZIP 가져오기·내보내기를 사용할 수 있습니다. 진단 복사는 표시된 내용을 복사하며, UTF-8 32KiB를 넘으면 생략 표시를 함께 보여 줍니다. 다운로드 리소스는 앱의 `Documents/IdolyPride`에 보관하며 iOS ‘파일’ 앱으로 접근합니다. 계정·설정과 준비한 언어 데이터는 `Library/Application Support/IdolyPrideLocal`에 보관합니다.

## 언어 데이터와 서버 구조

일본어 원본, 기존 한국어 데이터와 사전에 생성한 영어 데이터를 묶습니다. 게임 시작 전에 선택한 언어의 리소스 전용 번들을 준비하고 Unity가 그 번들을 읽도록 연결합니다. 공통 Data 파일은 검증된 캐시를 재사용하며, 언어별 파일은 해시를 검증해 준비합니다. 서명된 앱의 `Data`를 실행 중 덮어쓰거나, 게임 프레임마다 문자열을 번역하지 않습니다.

서버는 앱 안의 별도 작업 스레드에서 실행됩니다. macOS용 Python이나 별도 서버 프로세스를 실행하지 않습니다. 설정 WebView는 게임 진입·메뉴 닫기 때 해제하고, 모서리 영역은 터치를 시작할 때 현재 화면 크기로 계산합니다.

## 빌드와 검증

이번 세 플랫폼 릴리즈는 `.github/workflows/release-all-platforms.yml`에서 전체 회귀 검사와 성능 비교, Android·Mac·통합 IPA 실행 검사를 모두 통과해야 게시합니다. 기존 단독 IPA 후보 빌드는 `.github/workflows/build-server-apps.yml`의 `ios_unified=true`를 선택합니다. 기존 Android·Mac 릴리즈 작업과 별도로 Actions 후보 파일을 생성합니다. 선택적으로 `ios_publish=true`를 함께 지정하면 같은 소스·실행의 산출물과 전체 해시를 검증하고, 새 다운로드 브랜치에 게시한 IPA의 전체 재다운로드 해시까지 확인합니다.

1. `fetch_inputs.py`가 고정된 SHA-256으로 원본·한국어 IPA, 서버·번역 데이터, 영어 UI 입력, BeeWare iOS Python과 순수 Python 의존성을 검증합니다.
2. `tools/build_ios_client_languages.py`가 일본어·영어 Data와 언어별 매니페스트를 생성합니다. 한국어 파일과 공통 Data는 검증된 기존 한국어 앱을 사용합니다.
3. `native/test_client_data.py`, `native/test_keyboard_lifecycle.py`, `native/test_local_http.py`, `native/test_octo_budget.py`, `native/test_unity_host.py`와 `native/test_mac_menu.py`가 실제 macOS Foundation의 번들 선택·키보드 재사용·로컬 HTTP·형식을 확인한 SDK 설정 및 AppKit 메뉴·단축키를 검사합니다. SDK 설정 검사는 검사용 IL2CPP API 표를 사용하며 실제 Unity 실행과 구분합니다. `prepare_runtime.py`는 실제 iOS 플랫폼을 확인하고 Python 확장 모듈을 서명 가능한 프레임워크로 변환합니다.
4. `native/build_native.py`가 실제 Apple SDK로 서버 프레임워크를 빌드합니다. 검증된 Unity 초기화 진입점과 데이터 번들 선택 경로를 사용합니다. `patch_load.py`와 `package_unified.py`는 기존 게임 코드·SDK 바이트를 보존하고 필요한 로드 명령·앱 정보·추가 파일을 구성합니다.
5. `verify_client_languages.py`가 준비된 실제 Data로 일본어·한국어·영어 번들을 각각 재구성하고 다시 호출해 검증된 캐시 재사용을 확인합니다.
6. 새 Simulator용 프레임워크·검사용 앱에서 서버 시작·게임 진입·설정 메뉴 닫기 후 서버 유지, 창 크기별 네이티브 헤더와 설정 화면 배치, 진단 복사·클립보드 정리, 모서리 제스처 등록, CommonCrypto AES와 실제 암호화 RPC를 검사합니다. 암호화된 마스터 목록의 URL을 확인하고 서버에서 HEAD와 64바이트 부분 요청을 수행해 응답 크기·내용을 포함된 원본 파일과 대조합니다. 별도로 실제 서버의 암호화된 Octo 목록을 해독하고 원본 전체 항목·6글자 파일명을 검사한 뒤, 번역 이미지 한 개의 전체 응답을 해당 목록의 MD5·길이·ETag와 대조합니다. 원본 게임 실행 파일과 기존 Simulator·사용자 데이터는 사용하지 않습니다.

같은 새 앱 저장소에서 실제 WK 설정으로 다음 게임 언어를 저장하고 KO→EN→JA→EN→KO 다섯 번의 완전 재실행을 검사합니다. 각 실행은 서버 준비 후 게임 시작 전 최소 5초간 런타임이 시작되지 않았는지 관찰하고, 메인·서버 작업 스레드의 실제 끊긴 소켓 쓰기에서 EPIPE와 프로세스 생존을 확인합니다. 선택한 리소스·메타데이터의 전체 SHA-256과 돌아온 영어·한국어 파일의 동일성, 서버 UI의 JA→EN→KO 즉시 변경, 독립된 게임 창으로의 인계와 기존 검사를 모두 통과해야 합니다.

산출물에는 IPA와 SHA-256, 프레임워크·원본 보존 검사, 언어 데이터 검사 및 Simulator 결과를 함께 보관합니다. 자세한 경계는 [CONTRACT.md](CONTRACT.md)에 정리했습니다.

실제 iPhone·iPad의 터치·MV 재생·성능과 PlayCover의 MV 재생·성능은 별도 검증 대상입니다. Simulator의 가짜 Unity 진입점과 데이터 준비 검사는 실제 Unity 공연 실행 검사가 아닙니다. 검사용 가짜 Unity 코드와 우회는 기기용 IPA에 포함하지 않습니다. 선택적인 실험용 Go 라이브 시뮬레이터는 이 iOS 이식 범위에 포함하지 않았습니다.
